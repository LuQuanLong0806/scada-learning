〇、看文档前先认这 3 类东西（不然会云里雾里）

C# 世界里「写出来能跑的东西」分三类来源。本路线每个模块都会标注 🟦/🟩/🟧，请对照看：

  • 🟦 【C# 语法】 = 语言自带的关键字/写法。装好 .NET 就有，不用装任何包。 例：using、class、int、var、=> （对照 TS：let/const → var；: type → 类型写在前面；function → 方法）
  • 🟩 【.NET 类库 / BCL】 = 微软随 .NET 提供的"标准零件库"，using 对应命名空间即可用，默认不用额外装包。 少数（如 SerialPort）需加一行 dotnet add package System.IO.Ports——但它仍是微软官方库，不是第三方。 例：Console、List<T>、Dictionary、Math、Task、HttpClient、System.Text.Json、LINQ
  • 🟧 【第三方 NuGet 包】 = 别人写好的库，必须 dotnet add package 包名 才能用。 例：NModbus、S7.Net、LiveCharts、Serilog、MQTTnet、EF Core → 看到 using Xxx; 报错"找不到类型"，十有八九是要装 NuGet 包了。

💡 口诀：语法天生物、BCL 随 .NET、第三方要装包。

一、为什么改成「项目驱动」（你的策略，我加了 3 道保险）

你已经有中高级前端工程能力，真正的短板只是上位机专属领域知识（串口/Modbus/PLC/工业协议），这些只有写真实程序才学得会。所以「先学后练再应用」是最优解。我补 3 个保险防翻车：

  1. 精准预习：每个模块先给 10–20 分钟只学"本次用到的点 + 1 道练习"，再写代码 → 不盲目试错。
  2. 知识点串联地图（见第三节）：把 设备 → 串口/网口 → 协议 → 字节解析 → 业务对象 → 数据库 → 图表/报警 看成一条数据流水线，学一个就知道它接在链的哪一环。
  3. 企业级工程化（见第五节）：日志、配置化、断线重连、异常处理、MVVM 分层、测试意识——这些正好是 13K 面试必问的"工程化"分，功能是基础，工程化才是溢价。

怎么用这份文档：每模块按顺序走 ① 前置知识点（带 🟦🟩🟧 + 对比前端）② 练习 ③ 项目任务（落到 DAQ Monitor）。

二、选定项目：工业数据采集监控系统（DAQ Monitor）

为什么是它：这是工厂里上位机每天干的典型活——从 PLC/仪表采数据、解析、存库、画面实时展示、超限报警。一个项目覆盖 13K 全部要求，面试拿来讲最有说服力。

它长什么样（功能清单）： - 连接串口/网口设备，按 Modbus / S7 协议周期读取温度、压力、产量等数据点 - 实时曲线 + 数字面板展示，超限弹报警 - 数据落 SQLite 历史库，可查历史趋势 - 断线自动重连、运行日志记录 - 一键打包成可安装程序

三、知识点串联地图（数据流水线）

把整条链路记熟，考点就串起来了：

  1. 设备层：PLC、仪表、传感器——它们只认"寄存器/地址 + 数值"。
  2. 传输层：串口（RS485，SerialPort 🟩）或网口（TCP Socket 🟩）。→ 对应 M1/M3
  3. 协议层：Modbus RTU/TCP（🟩手搓 + 🟧NModbus）、西门子 S7（🟧S7.Net）。协议 = "怎么把'读地址100的温度'打包成字节发给设备，再把回的字节解出来"。→ 对应 M2/M4
  4. 解析层：字节序（大小端）、BitConverter 🟩、类型转换——把原始字节变成 float temperature。→ 贯穿 M2–M4
  5. 业务层：变成 SensorData 等业务对象，用 List<T>/LINQ 🟩 处理。→ M2 起
  6. 存储层：SQLite + EF Core 🟧 落历史库。→ M5
  7. 展示层：WPF Binding/MVVM 🟩 + LiveCharts 🟧 实时曲线（类比前端：Binding≈v-model，LiveCharts≈echarts）。→ M6
  8. 报警层：阈值判断 + 弹窗 + Serilog 🟧 日志。→ M6/M7

考试常问"Modbus 一帧怎么组成的""大小端怎么处理""为什么要用 MVVM"——答案都在这条链上，串起来就不会慌。
