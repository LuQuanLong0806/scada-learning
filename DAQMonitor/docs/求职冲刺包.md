#### Q2. WPF 的 MVVM 跟 React/Vue 有什么相同和不同?
**话术**:
> 相同点:都是"状态驱动 UI",ViewModel 的属性变化自动反映到 View,跟 React 的 useState 类似。
> 不同点:
> 1. WPF 的绑定是**双向的**(TwoWay),React 是单向 + 受控组件
> 2. WPF 用 `INotifyPropertyChanged`,每个属性 setter 手动触发;Vue 是响应式代理,React 是不可变状态
> 3. WPF 的 `ICommand` 把"按钮可用性"和"执行逻辑"绑在一起(`CanExecute` + `Execute`),React 是 disabled 属性 + onClick 两件事
> 4. WPF 有依赖属性系统(支持继承、动画、样式优先级),前端没有等价概念

#### Q3. INotifyPropertyChanged 怎么实现的?有没有更好的方式?
**话术**:
> 项目里我用最朴素的方式:
> ```csharp
> public bool IsRunning {
>     get => _running;
>     set { _running = value; OnChanged(); }
> }
> private void OnChanged([CallerMemberName] string? n = null)
>     => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(n));
> ```
> `[CallerMemberName]` 自动取属性名,避免手写字符串。
>
> **更好的方式**(面试加分):
> - **CommunityToolkit.Mvvm** `[ObservableProperty]` 特性 — 源生成器自动生成 setter
> - **PropertyChanged.Fody** — IL 织入,运行时零反射
>
> 项目里没用是为了"每行都能讲",真实工程我会用 CommunityToolkit。

#### Q4. 串口通讯怎么处理粘包/分包?
**话术**:
> 这是工业现场最高频问题。3 种主流方案:
> 1. **固定长度帧**:每个包 N 字节,读够就处理(简单但不灵活)
> 2. **特殊分隔符**:比如 `\r\n` 或 `0xAA 0x55`(常见于老旧仪器)
> 3. **帧头 + 长度字段**(我用的方式):比如 `[0xAA][len_hi][len_lo][payload][crc]`,读到 0xAA 后按 len 等够
>
> 项目里 `FrameParser` 实现了状态机:`WaitingHead` → `ReadingLen` → `ReadingPayload` → `VerifyingCRC`,任意一步失败回 `WaitingHead`。CRC 错也回 `WaitingHead`,**不丢数据但要重同步**。

#### Q5. Modbus 协议你了解多少?RTU 和 TCP 区别?
**话术**:
> Modbus 是工业最常用的"事实标准"协议,40+ 年了。两种主要形态:
> - **RTU**:跑串口(RS-232/485),二进制帧 + CRC16 校验,主从模式
> - **TCP**:跑以太网,去掉了 CRC(由 TCP 层保证),用 MBAP 头(7 字节)
>
> 项目里 `ModbusFrameParser` 实现了 RTU 帧解析,支持 4 种数据类型:
> - Coil(线圈,1 位,bool)
> - Discrete Input(离散输入,1 位只读)
> - Input Register(输入寄存器,16 位只读)
> - Holding Register(保持寄存器,16 位可读写)— **最常用**
>
> **浮点字节序**:Modbus 寄存器是 16 位,存 float 要 2 个寄存器。字节序有 4 种(ABCD/DCBA/BADC/CDAB),**西门子是 CDAB,三菱是 ABCD**,接 PLC 第一件事就是抓帧确认字节序。

#### Q6. EF Core 的 DbContext 为什么要用 IDbContextFactory?
**话术**:
> 因为 `DbContext` **不是线程安全的**,默认是 scoped 生命周期(一个请求一个实例)。在我的项目里有 3 类并发线程:
> 1. UI 线程(WPF Dispatcher)
> 2. 采集管道的消费者线程(`Channel<SensorPoint>` 后台读取)
> 3. BackgroundService(异步写库泵)
>
> 如果它们共享一个 DbContext,EF 会抛 `InvalidOperationException: A second operation was started on the context before a previous operation completed`。
>
> 解决:**注入 `IDbContextFactory<AppDb>`,每段代码 `using var db = factory.CreateDbContext()`**,每个线程独立 DbContext,互不干扰。这是 EF Core 5+ 的官方推荐模式。

#### Q7. 怎么实现按钮级别的权限控制?
**话术**:
> 项目里 3 层防护:
> 1. **后端层(Service)**:`RecipeService.CreateAsync` 检查 `_current.HasPermission(Permissions.RecipeEdit)`,无权限直接抛异常

#### Q8. 用户密码怎么存的?为什么不用 MD5?
**话术**:
> 项目用 **BCrypt(workFactor=11)**,单次验证约 200ms。
>
> 为什么不用 MD5/SHA:
> 1. **MD5/SHA 是哈希算法,不是密码哈希算法** — 设计目标不同:哈希追求快,密码哈希追求慢
> 2. **快 = 容易爆破** — GPU 每秒能算几亿次 MD5,字典攻击几分钟破解
> 3. **BCrypt 自带 salt** — 每次哈希结果不同,彩虹表无效
> 4. **workFactor 可调** — 硬件升级后调高(11→13),抗 GPU/ASIC
>
> **时序安全**:项目里用户不存在时也跑一次 `BCrypt.Verify("dummy", hash)`,防止"用户不存在秒返回,存在慢返回"侧信道攻击。
>
> 真实工程升级路径:Argon2id(2015 密码哈希竞赛冠军),但 BCrypt 仍是工业主流。

#### Q9. 审计日志为什么不能 try/catch 直接抛?
**话术**:
> 因为工业现场铁律:**审计失败不应中断业务**。
>
> 场景:操作工点"启动采集",AuditService 想写"用户 X 启动了采集",但 SQLite 文件被杀毒软件锁住了。如果直接抛异常:
> - 操作工看到"启动失败",以为系统坏了
> - 实际上采集已经启动了
> - 现场停机损失巨大
>
> 项目里的处理(`AuditService.LogAsync`):
> ```csharp
> try { db.AuditLogs.Add(log); db.SaveChangesAsync(); }
> catch (Exception ex) { Console.Error.WriteLine($"[AUDIT FAIL] {action}: {ex.Message}"); }
> ```
> 异常吞掉,业务继续。但**关键路径(如登录)**的审计可以让 LogAsync 抛 — 这是业务决策。
>
> FDA 21 CFR Part 11 要求审计完整,生产环境会加双写:SQLite + 本地文件 + 远程日志服务,任何一个失败仍保留其他副本。

#### Q10. 实时曲线怎么避免 UI 卡顿?
**话术**:
> 项目 10Hz × N 点位的实时曲线,3 个关键点:
>
> 1. **跨线程同步用 Dispatcher**:`Application.Current.Dispatcher.Invoke(() => { /* 改 UI 绑定集合 */ })`,采集线程不能直接改 ObservableCollection
> 2. **批量更新**:`BatchReady` 事件每 200ms 触发一次,而不是每个点位都刷 UI
> 3. **滑动窗口**:LiveCharts2 配置 `IEffectsView` 的 limit,只渲染最近 N 个点(比如 600 个 = 1 分钟)
>
> 性能上限:单曲线 60Hz × 1 小时(21.6 万点)就明显卡。优化方向:
> - 降采样(每 N 个点取 1 个)
> - 切换 OxyPlot(对历史数据更友好)
> - 用 SkiaSharp 自绘(性能最高,代码量也最高)

#### Q11. 设备断线重连怎么做的?
**话术**:
> 项目里 `DeviceHealthMonitor`(M9 模块)封装了这个流程:
> 1. **心跳探活**:每 5 秒读一个寄存器(或发个 ping),正常返回 → 心跳计数清零
> 2. **连续 miss 2 次进入断线态**:`DeviceState.Disconnected`,触发 `StateChanged` 事件
> 3. **指数退避重连**:1s → 2s → 4s → 8s → 上限 30s(避免网络抖动期间疯狂重试)
> 4. **重连成功恢复采集**:不丢数据(因为采集管道里有 Channel 缓冲)
>
> 工业现场常见故障模式:
> - 串口:USB 转串口松动(拔插后 COM 号可能变)
> - TCP:网线断了、IP 冲突、防火墙
> - PLC:停机维护时,后台轮询会爆错误日志 — 重连策略要识别"管理性停机"vs"故障"

#### Q16. DI 容器跟 new 有什么区别?什么场景必须用 DI?
> DI 的价值:**生命周期管理 + 解耦 + 可测试**。
> - `new` 是写死依赖,换实现要改代码
> - DI 容器统一注册,运行时按需解析,实现可替换
> - 测试时可以 Mock 接口注入
>
> 必须用 DI 的场景:
> 1. 同一个接口有多个实现(`IEnumerable<IAxisController>` 自动收集所有 X/Y/Z 轴)
> 2. 跨层共享单例(`PointStore` 全局唯一)
> 3. 需要复杂生命周期(scoped/transient/singleton)
>
> 项目里 `Bootstrapper.Build()` 是组合根,**只在程序入口调一次**,然后 `provider.GetRequiredService<T>()` 取服务。

#### Q17. C# 的 async/await 跟 JS 的 Promise 有什么区别?
> 表面像,底层不同:
> - **JS 是单线程事件循环**,async/await 是 Promise 的语法糖,await 让出执行权,UI 不阻塞但本质串行
> - **C# 是多线程**,async/await 编译成状态机,默认在 ThreadPool 跑,真并发
>
> WPF 特殊点:`await Foo()` 后默认回到 UI 线程(`SynchronizationContext`),不需要手动 Dispatcher。但 `Task.Run(() => ...)` 内部就要 Dispatcher 才能改 UI。
>
> 项目里:`AcquisitionPipeline` 的消费者线程在 ThreadPool,改 UI 用 `Application.Current.Dispatcher.Invoke(...)`。

#### Q18. lock 和 Monitor 有什么区别?
> `lock(obj) { ... }` 是 `Monitor.Enter/Exit` 的语法糖,等价的。
>
> 进阶区别:
> - `Monitor.TryEnter(timeout)` — 可超时,lock 不行
> - `Monitor.Wait/Pulse/PulseAll` — 类似 Java 的 wait/notify,做生产者-消费者
> - `SemaphoreSlim` — 限制并发数(比如最多 3 个线程同时访问)
> - `ReaderWriterLockSlim` — 读多写少场景(我们项目的历史查询)
>
> 项目用 lock 是因为简单 + 频率低(登录/登出/换班)。高频场景我会换 `Interlocked`(无锁,更快但只能原子读写)。

#### Q19. PLC 跟运动控制卡的区别?
> 这是现场最常见"懂工艺"面试题:
> - **PLC**:可编程逻辑控制器,扫描周期 1-4ms,IEC 61131-3 编程(梯形图/ST),适合**逻辑控制 + 简单定位**
> - **运动控制卡**:插 PC 里(PCIe/USB),CPU 直接发脉冲/通过总线(EtherCAT/PROFINET),适合**高速高精度多轴同步**
>
> 工业分工:
> - 简单设备(单机):PLC 控制就够,上位机只是监控
> - 复杂设备(多轴凸轮/龙门同步/飞拍):运动控制卡,上位机管工艺流程
> - 大型产线:PLC + 独立 IPC 跑视觉 + SCADA 总览
>
> 项目里 `IAxisController` 抽象兼容两者,接口对齐 PLCopen Motion 标准 — PLC 也能实现这个接口(用 S7-net/OPC UA 走协议)。

#### Q20. 你了解 IEC 62443 / 21 CFR Part 11 吗?
> 这是**工业合规加分题**,80% 的候选人不知道:
>
> **IEC 62443** 工控网络安全标准:
> - Zone & Conduit 概念:把网络分区域,区之间用防火墙
> - 安全等级 SL1-4:SL1 是基本防护,SL4 是国家级攻击防护
> - 项目里"断网车间"决策就符合 Zone & Conduit 思路
>
> **FDA 21 CFR Part 11** 电子记录电子签名(医药/食品):
> - 任何工艺参数变更必须可追溯(配方版本历史)
> - 电子签名(用户 + 时间戳 + 不可篡改)
> - 项目 M17 审计 + M18 配方快照就是为这个标准设计的
>
> **IEC 60204-1** 机械电气安全:急停电路必须独立于 PLC/上位机(硬件回路),E-Stop 按钮直接断伺服电。项目 `EmergencyStopAsync()` 是软件层,真实还有一层硬件急停。

#### Q21. 报警的滞后量(Hysteresis)是干什么的?
> **防止数据抖动导致的"狼来了"**。
>
> 场景:温度阈值 100℃,实际温度在 99.5-100.5 之间抖动(传感器噪声):
> - **无 Hysteresis**:每秒触发/恢复/触发/恢复 N 次,操作工疯掉
> - **Hysteresis=2**:超 100 触发,必须降到 98 以下才恢复 — 抖动期不再"狼来了"
>
> 项目 `AlarmRule` 的 Hysteresis 字段:`Threshold=100, Hysteresis=2` → 触发线 100,恢复线 98。
>
> 这是工业现场工程师的常识,但前端转来的没经验,容易忽略。

#### Q22. 配方管理你怎么做的?激活时怎么保证全局唯一?
> 项目 M18 的核心契约:**同时只能有一个激活配方**。
>
> 实现用 **DB 事务**保证原子:
> ```csharp
> using var tx = await db.Database.BeginTransactionAsync();
> foreach (var r in await db.Recipes.Where(r => r.IsActive).ToListAsync())
>     r.IsActive = false;
> recipe.IsActive = true;
> await db.SaveChangesAsync();
> await tx.CommitAsync();
> ```
>
> 配套:
> - **版本自增**:每次 Update 自动 +1
> - **自动快照**:Update 前存档到 `RecipeSnapshot` 表,可回滚任意版本
> - **软删除**:`IsDeleted=true` 而非物理删(审计链不断)
> - **JSON 列存参数**:`ParametersJson` 字段,EF Core 8 + System.Text.Json
>
> 满足 FDA 21 CFR Part 11 对配方变更追溯的要求。

#### Q23. 运动控制卡你用过哪家?回零流程是什么?
> 诚实回答:**项目用模拟实现**,但接口设计对标 PLCopen Motion 标准,真卡接入只需替换 `IAxisController` 实现。
>
> 回零流程(行业通用):
> 1. 轴以 HomeVelocity(慢速,通常 20% MaxVel)向**回零开关方向**运动
> 2. 碰到回零开关(硬件 IO 信号)→ 减速停止
> 3. 反向脱离一小段距离(避免机械应力)
> 4. 找**编码器 Z 相**(每转一圈一个的零位脉冲)
> 5. Z 相触发瞬间记录当前位置 = 0 点(用户单位)
>
> 为什么不直接用回零开关位置作零点:回零开关有机械公差(±0.1mm),Z 相精度到 ±1 脉冲(0.0001mm)。
>
> 飞拍(On-the-Fly Capture)是另一回事:运动中触发电机抓拍,靠 Position Compare Output(轴走到指定位置时硬件发 IO 脉冲)。

#### Q27. MES 对接你会怎么设计?
**话术**:
> MES(制造执行系统)对接通常 3 种形态:
> 1. **REST/HTTP**:最简单,MES 提供 API,我们上报工单/良率/状态。适合 IoT 时代新 MES
> 2. **WebSocket**:双向,适合实时下发命令(换型、参数变更)

> - **断网缓存**:Channel<T> 队列,联网后批量补传

>
> 工业现场真相:**很多 MES 项目半死不活**(贵、定制化深、运维跟不上),所以**断网可降级**是关键 — 不能 MES 挂了产线就停。

#### Q28. 飞拍(On-the-Fly Capture)是什么?Position Compare Output 怎么实现?
> 飞拍 = 运动中触发电机抓拍,无需停机 — 高速产线必备(比如 200 mm/s 移动同时拍 100 个产品)。
>
> 实现:**Position Compare Output**(位置比较输出)。
> - 运动控制卡硬件功能:轴走到指定位置时,**硬件层**直接发一个 IO 脉冲(不经过 PC 软件,延迟 < 1us)
> - 这个脉冲接到相机 Trigger 输入,触发曝光
> - PC 软件事后从轴读"位置 X 触发"事件 + 从相机取图,对账
>
> 项目没实现飞拍(需要真硬件),但接口预留:`IAxisController` 加 `SetPositionCompareOutput(position, outputPort)` 即可,模拟实现记事件。
