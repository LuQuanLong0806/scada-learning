# DAQMonitor UI 原型图设计指南

> **目的**:面试官打开 GitHub 第一眼看到 UI 设计,5 秒内判断"这人专业"。原型图 3 个核心价值:① 简历加分 ② 面试展示讲法 ③ 操作工视角验证可用性。
> **三阶段制作**:① ASCII(5min,放进 README 立刻可见) ② Excalidraw(30min,3 个核心页 PNG) ③ Figma(Day 22-23 文档周,多页 + 组件库)。

---

## 工业上位机 UI 设计 5 大原则(必须懂)

| 原则 | 含义 | 反例 |
|---|---|---|
| ① **信息密度优先** | 操作工一眼看完全部关键数据,不滚动 | 把温度藏在第 3 层菜单 |
| ② **报警颜色严格** | 红=严重 / 黄=警告 / 绿=正常 / 灰=离线,**不能乱用** | 用红色画背景,报警看不出 |
| ③ **盲操作友好** | 关键按钮大(>48px),状态用图标+文字双表达 | 仅用颜色区分状态(色盲操作工看不清) |
| ④ **7×24 不疲劳** | 深色模式优先(夜班),高对比,无闪烁动画 | 大面积纯白背景 + 闪烁红光 |
| ⑤ **状态可追溯** | 当前值 + 趋势曲线 + 历史报警,3 件套并排 | 只显示当前值,不知道趋势好坏 |

**前端类比**:这 5 条比 B 端中后台严格多了。中后台错了用户投诉,上位机错了**可能炸设备 / 工伤**。所以面试时讲"我为什么这么设计",讲原则比讲美观值钱 10 倍。

## 阶段 2:Excalidraw 30 分钟实操指导

### 2.1 准备
1. 打开 [excalidraw.com](https://excalidraw.com)(免费,不用注册,本地保存)
2. **设置背景颜色**:`#1E2A38`(深蓝灰,模拟深色模式)
3. **画笔粗细**:常规 2px,边框 1px,填充用透明度 20%
4. **字体**:Cascade / 手写体,字号 16-20px

### 2.2 画 3 个核心页面(按优先级)

**Page 1: 主界面(15 分钟)** — 必须画

布局尺寸(1920×1080):
```
Header:    1920 × 50px(顶部)
Sidebar:   120 × (1080-50-30) = 120 × 1000(左侧)
Main:      1480 × 1000(中)
Right:     320 × 1000(右侧报警 + 日志)
Footer:    1920 × 30px(底部)

Main 内部:
  Tab Bar:     1480 × 40
  实时曲线:    1480 × 400
  实时点位表:  1480 × 560
```

画法:
1. 先画 5 个大矩形(Header / Sidebar / Main / Right / Footer)
2. Sidebar 里画 6 个导航图标(📊📅🔔🔧📋⚙)用 Excalidraw 自带 icon
3. Main 里画一个曲线占位(用 pen 工具画手绘曲线)
4. Right 里画 2 个矩形(报警 + 日志)
5. 用箭头工具标注关键交互("点击 → 跳转设备页")

**Page 2: 报警历史(10 分钟)** — 必须画

简化布局,只画 Header + Sidebar + Main 表格区,Right Panel 复制 Page 1。

**Page 3: 报表导出(5 分钟)** — 选画

只画 Header + Sidebar + Main 表单 + 预览表格。

### 2.3 导出 PNG

1. `File → Export → PNG`
2. **质量选项**:Scale = 2x(高清),Background = Transparent(透明)
3. 保存为 `mockup-main.png` / `mockup-alarm.png` / `mockup-report.png`
4. 放进 `DAQMonitor/docs/mockup/` 目录

## 面试会问什么(8 题)

1. **Q: 你的 UI 是怎么设计的?**
   A: 先画原型图(Excalidraw + Figma),定 5 大原则(信息密度 / 报警颜色严格 / 盲操作友好 / 7×24 不疲劳 / 状态可追溯),然后才写 XAML。

2. **Q: 为什么用深色模式?**
   A: 工业现场夜班多,深色减少眼睛疲劳;报警颜色(红/黄)在深色背景下对比度更高,操作工一眼看到。

3. **Q: 报警颜色为什么这么严格?**
   A: 工业标准 IEC 60073 规定:红=立即处理 / 黄=异常但可运行 / 绿=正常 / 灰=离线。乱用颜色会让操作工麻木,真正报警时反应慢。

4. **Q: 操作工用鼠标还是触屏?**
   A: 现场越来越多触屏工控机,所以关键按钮 > 48px(指尖点击区域),状态用图标+文字双表达(色盲也能识别)。

5. **Q: 你怎么验证 UI 可用性?**
   A: 拿原型图给现场操作工看(或模拟操作工走查),记录他们:① 第一眼看哪里 ② 找报警要多久 ③ 误点率多少。原型图阶段改 1 次比代码阶段改 10 次便宜。

6. **Q: 实时曲线为什么不卡?**
   A: 三招:① 60s 滚动窗口,超出窗口数据丢 ② LiveCharts2 用 SkiaSharp 渲染(GPU 加速)③ 数据降采样,1 万点压成 1 千点显示。

7. **Q: 多设备类型怎么布局?**
   A: Sidebar 一级导航按"功能"分(实时/历史/报警/设备/报表/设置),不按"设备类型"分。这样加新设备类型只改"设备管理"页,主界面布局不动。

8. **Q: 你前端经验怎么转化?**
   A: Figma 直接复用(画法一样)/ 配色规范从前端 Tailwind 平移 / 组件化思维(DeviceCard 像 React 组件,有 props 和 states)/ ECharts 思维模型直接套 LiveCharts2。
