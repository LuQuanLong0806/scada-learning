模块目标

public class ChartVm : INotifyPropertyChanged

    };

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string? name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}

③ 实时追加（事件→入队→定时批量）（呼应 M0 Day 7 跨线程 + M5② 批量刷新）

🔥 修正说明：早期版本在 DataReceived 里用 Dispatcher.Invoke 逐点刷新 UI —— 100Hz×多设备时直接卡死。正确做法是：事件只负责入队，UI 用定时器批量刷新。

// 1) 事件只做“入队”这件极轻的事（线程安全，不阻塞采集线程）
var ch = System.Threading.Channels.Channel.CreateUnbounded<SensorPoint>();
device.DataReceived += (s, e) =>
    ch.Writer.TryWrite(new SensorPoint { Id = e.PointId, Value = e.Value, Timestamp = e.Timestamp });
    // ⚠️ e 是 DataEventArgs(PointId/Value/Timestamp),要转成 SensorPoint — Timestamp 必须抄!

// 2) UI 线程用 DispatcherTimer 每 500ms 定时“批量拉取”一批，一次性画曲线
var timer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(500) };
timer.Tick += (_, _) =>
{
    var batch = new List<SensorPoint>();
    while (ch.Reader.TryRead(out var p)) batch.Add(p);   // 取出这一批
    if (batch.Count == 0) return;
    var series = (LineSeries<ObservablePoint>)vm.Series[0];
    foreach (var p in batch)                              // 批量追加，不是逐点
        series.Values.Add(new ObservablePoint(p.Timestamp.Second, p.Value));
    while (series.Values.Count > 200) series.Values.RemoveAt(0); // 限长防内存涨
};
timer.Start();

📌 更完整的企业级封装见 M9 统一采集架构（AcquisitionPipeline）：用 Channel<T> + Timer 把“可视化 / 报警 / 上云”统一成「事件→入队→定时批量」一条流水线，避免每个模块各写一套逐点刷新。

🔬 掰开揉碎：为什么用 Channel<T> 而不是直接 ObservableCollection.Add

直觉上「收到点就 series.Values.Add 不行吗？」在低频(1Hz)下可以，但工业是 100Hz×多设备： - ObservableCollection.Add 会立刻通知 UI 重绘：每加 1 个点，WPF 就重画一次曲线。100Hz = 每秒重绘 100 次，UI 线程直接被打满 → 卡死/掉帧。 - Channel<T> 是无锁队列缓冲：Writer.TryWrite 是 O(1)、线程安全、几乎零开销，只把点存进去，不碰 UI。然后 DispatcherTimer 每 500ms 一次性「取出这一批 → 批量 Add」，重绘频率从 100 次/秒降到 2 次/秒。 - 一句话：Channel 把「高频生产」和「低频消费」解耦，这正是 M9 统一采集管道的核心思想（可视化/报警/上云全从 BatchReady 批量取）。

⚠️ 重点 & 易踩坑

项 说明
⭐ 事件里只入队 DataReceived 是高频率后台回调，里面只做极轻操作，重活交给定时器
⭐ 跨线程改 UI 要回 UI 线程 DispatcherTimer 的 Tick 自动在 UI 线程；若订阅后台线程事件（如 M9 的 BatchReady）要用 Dispatcher.Invoke
⭐ 限制点数 曲线无限增长 = 内存泄漏 + 卡顿，固定窗口(如 200 点)
🔥 绑定没生效 Series 要 public 属性 + 实现通知，或用 ObservableCollection
🔥 高频刷新卡 别每毫秒刷新，定时(100~500ms)批量更新

🟢 基础题

建一个 ChartVm，用 DispatcherTimer 每 500ms 往曲线加一个随机数点，限制 100 点。

🟡 进阶题

把曲线改成"双序列"（温度+压力两条线），用不同颜色，各限制 200 点。

🔴 挑战题

用 Channel<T> 做缓冲（仿 M9 统一管道）：后台 Task.Run 每 50ms 产一个点 TryWrite 入队，UI 定时器每 500ms 批量取 10 个画曲线——体会"高频生产 / 低频消费"解耦。

✅ 答案（基础题核心）

var timer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(500) };
timer.Tick += (_,_) =>
{
    var s = (LineSeries<ObservablePoint>)vm.Series[0];
    s.Values!.Add(new ObservablePoint(DateTime.Now.Second, Random.Shared.NextDouble()*100));
    if (s.Values.Count > 100) s.Values.RemoveAt(0);
};
timer.Start();

Day 2 — 仪表盘 + 性能 🟡

一句话讲清楚

仪表盘（Gauge）用一个"指针"显示当前值，适合监控单点(如总压)；配合曲线组成监控大屏。

分点精讲

① 仪表盘（🟧）

public ISeries[] Gauge => new ISeries[]
{
    new PieSeries<double> { Values = new double[]{ Current }, InnerRadius = 60, MaxValue = 200 }
};
private double _current;
public double Current { get => _current; set { _current = value; OnPropertyChanged(); } }

② 性能要点（🟦 架构） - 用 DispatcherTimer 而不是每个事件都刷新 - 数据层用 Channel<T> / ConcurrentQueue 缓冲，UI 定时批量取 - 关闭 Animation 高频场景可提速：new LineSeries<ObservablePoint>{ AnimationsSpeed = TimeSpan.Zero }

⚠️ 重点 & 易踩坑

项 说明
⭐ 单一数据源 Current 用属性通知，仪表盘/曲线共用，别各算各的
⭐ 批量刷新 100Hz 数据别逐点刷 UI，攒 100ms 一批
🔥 内存 所有集合都要限长

🟢 基础题

给仪表盘加一个 MaxValue=200，并用 Current 属性通知驱动指针。

🟡 进阶题

做两个仪表盘（总压 / 温度），各绑定不同点位，超限时指针变红（接 M6 报警级别）。

🔴 挑战题

把"曲线 + 仪表盘 + 实时数值列表"三件套拼成一个监控页，数据全部来自同一个 Channel<T> 批量出口（M9 的 BatchReady），验证"一个数据源，多个消费者"的架构价值。

✅ 答案（基础题核心）

public ISeries[] Gauge => new ISeries[]
{
    new PieSeries<double> { Values = new double[]{ Current }, InnerRadius = 60, MaxValue = 200 }
};
private double _current;
public double Current { get => _current; set { _current = value; OnPropertyChanged(); } }

🧩 多场景应用：实时可视化还能怎么用

同一个 LiveCharts2，换个数据源/配置就是不同场景，图表代码不用重写： - 实时曲线（本模块）：DispatcherTimer 批量追加，限长窗口。 - 历史回放：读 M4 数据库按时间窗查点，一次性画整段曲线——把"实时入队"换成"查库出列"。 - 多通道叠加：多个 LineSeries 绑不同点位，同图对比（如 3 个温区）。 - 报警带 / 阈值线：在曲线上画红色 VisualElements 或辅助 LineSeries，联动 M6 阈值，超限区高亮。 - 导出图片：图表截图存盘，进 M10 报表。 - 车间大屏看板：多个 Gauge + 曲线 + StatusDot 拼一屏，对接 LED 墙。

💡 核心套路："数据从哪来"和"怎么画"分离——换数据源（实时/历史/多设备）只改 ViewModel，图表代码不变。这正是 M9 统一管道「一个 BatchReady，多个消费者(可视化/报警/上云)」的思想。

📌 温故知新（跨模块联动）

  • M0 Day7 后台线程 → 这里 Dispatcher/Channel：后台收数不能直接改 UI，要么 Dispatcher.Invoke(M0)，要么入队批量(M9)，本质都是「别在采集线程碰界面」。
  • M1–M3 点数据 → 这里画出来：可视化是采集链的「输出端」，没前面的设备接入就没东西画。
  • M9 统一管道 → 这里是其第一个消费者：BatchReady 批量取点画曲线，比本模块手搓 Channel 更彻底（报警 M6、上云 M7 共用同一批）。

🧩 完整代码组装（ChartVm + 批量刷新，可直接抄）

// ViewModels/ChartVm.cs
public class ChartVm
{
    public ISeries[] Series { get; } =
    {
        new LineSeries<ObservablePoint> { Values = new ObservableCollection<ObservablePoint>(), Fill = null }
    };
}
// MainWindow.xaml.cs —— 事件只入队，定时器批量画
var ch = Channel.CreateUnbounded<SensorPoint>();
device.DataReceived += (s, e) => ch.Writer.TryWrite(
    new SensorPoint { Id = e.PointId, Value = e.Value, Timestamp = e.Timestamp });
var timer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(500) };
timer.Tick += (_, _) =>
{
    var batch = new List<SensorPoint>();
    while (ch.Reader.TryRead(out var p)) batch.Add(p);
    var s = (LineSeries<ObservablePoint>)vm.Series[0];
    foreach (var p in batch) s.Values.Add(new ObservablePoint(p.Timestamp.Second, p.Value));
    while (s.Values.Count > 200) s.Values.RemoveAt(0);
};
timer.Start();
