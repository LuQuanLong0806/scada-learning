一、C# 语言基础

E01 · 接口 interface / 类 class / :base / 访问修饰符 🔴

你的原话:"接口 类 :base 访问修饰符"

一句话总纲:interface 定合同(能做什么),class 实现合同(怎么做),:base(...) 接通父子构造链,访问修饰符划可见边界——四个东西共同回答"类型之间怎么连接"。

1. interface —— 运行期真实存在的合同

public interface IDevice
{
    int Id { get; }                                   // 属性:只有签名
    void Connect();                                   // 方法:只有签名
    event EventHandler<DataEventArgs>? DataReceived;  // 还能声明事件
}
  • 接口成员不许写访问修饰符——写 public 直接编译错。合同条款天然全公开,不存在"半公开的条款"。
  • 接口不能有字段、不能有构造函数——它只描述"你能对我做什么",不描述"我肚子里的数据"。
  • 和 TS interface 的核心差异:TS 的 interface 编译成 JS 后不存在了(纯类型标注,擦除);C# 的 interface 编译后真实存在——能 is IDevice 判断、能当 DI 容器的注册类型、能多态分发。前端类比:像 TS interface 有了"运行期的灵魂"。

实现接口(和继承共用一个冒号):

public class SimulatedDevice : DeviceBase, IDevice
//                              ↑ 基类在前     ↑ 接口在后,逗号分隔

C# 单继承、多接口:基类最多 1 个,接口随便几个,顺序必须基类在最前。TS 的 extends B implements C, D 到 C# 里全部挤进冒号后面。

2. :base(...) —— 子类构造函数接通父类

项目实物(R2 的 DeviceBase → SimulatedDevice):

public abstract class DeviceBase : IDevice
{
    protected DeviceBase(int id, string name) { Id = id; Name = name; }
}

public class SimulatedDevice : DeviceBase
{
    public SimulatedDevice(int id, string name, params int[] pointIds)
        : base(id, name)                    // ← 就是 JS 的 super(id, name)
        => _pointIds = pointIds;
}
  • 为什么必须写:DeviceBase 只定义了带参构造(没写无参构造),子类构造必须显式替父类"传参"。不写 : base(...) 编译错 CS7036:"DeviceBase 不包含采用 0 个参数的构造函数"。
  • 执行顺序:子类字段初始化器 → :base(...) 父类构造体 → 子类构造体。ES6 同款规矩:super 先于 this。
  • base 的第二个用法:base.方法() 在子类里调父类成员,等价 super.method()——主要用于"重写之后还要调一次原版"。项目里子类直接调 RaiseData()(继承来的),不需要 base 前缀。

3. 访问修饰符 —— 六档可见性,先记三档

修饰符 谁能看见 前端类比
public 所有人 export
private 类成员默认! 本类内部 模块内不 export 的变量
protected 本类 + 子类 没直接对应;可理解为"专门留给子类碰的钩子"
internal 同一程序集(同一个编译出的 dll/exe) monorepo 包内可见、不对外发布的内部模块
protected internal / private protected 组合档,入门阶段不用碰 —

三个高频易错:

  1. C# 类成员默认 private,TS 默认 public——前端转过来最容易翻车的一处。C# 里不写修饰符的方法,出了这个类全不可见。
  2. 接口成员不能写修饰符(上面说过);但接口本身该写 public 还是要写(要对程序集外可见时)。
  3. 属性的读写可以拆开:public DeviceState State { get; protected set; }——读公开、写只留给子类。项目里 DeviceBase.State 就是这个设计:UI 只能看设备状态,只有设备自己(子类)能改,状态机的修改权收进设备内部。访问修饰符不只是"权限标注",是设计工具。

自测(全对再翻篇)

  1. interface 的方法写 public void Connect(); 会怎样?为什么?
  2. 基类只有 (int, string) 构造,子类构造不写 : base(...) 会怎样?
  3. class A : B, IC, ID 合法吗?B、IC、ID 各是什么?顺序能换吗?
  4. public int X { get; private set; } 和 public int X; 的区别?
  5. C# 类成员不写修饰符默认是什么?TS 呢?
答案(先自己答再看)
  1. 编译错——合同条款天然全公开,不需要再标 public。
  2. CS7036 编译错——父类没有无参构造,子类必须显式传参。
  3. 合法。B 是基类(最多一个),IC/ID 是接口(可多个);基类必须排在最前,不能换。
  4. 前者是属性:外部只读(set 私有);后者是公开字段,外部随便改。
  5. C# 默认 private;TS 默认 public。

二、异步与多线程

E02 · Task.Run / Task.Delay / 异步循环 🔴

你的原话:"Task.Run Task.Delay loop 等相关的我很不熟"

一句话总纲:Task 是"将来完成的工作"(≈ Promise),Task.Run 把工作丢线程池(≈ 真并行的 setTimeout),Task.Delay 异步睡不占线程(≈ sleep 但必须 await),异步循环 = "等一拍、走一步"。

1. 概念总表(对照 JS)

C# 是什么 JS 对照 本质差异
Task 一次将来完成的工作 Promise Task 可能跑在别的线程(真并行);JS 永远单线程
Task.Run(fn) 把 fn 丢线程池,立刻返回 setTimeout(fn, 0) setTimeout 还是原线程回头执行;Task.Run 是另一个核并行跑
await Task.Delay(ms) 异步等 ms,线程被释放 await sleep(ms) 完全同构;不 await 就什么都没发生
Thread.Sleep(ms) 阻塞当前线程干等 (JS 没有对应) UI 线程上 Sleep = 界面冻结;永远别在 UI 线程用

2. Task.Run —— "丢到后台,我继续干我的"

// R2 SimulatedDevice:Start() 立刻返回,采集循环在后台跑
_cts = new CancellationTokenSource();
_loop = Task.Run(() => LoopAsync(_cts.Token));   // 丢给线程池,这行立即往下走
  • 返回 Task:不 await 它,当前代码"发射后不管"(fire-and-forget);await 它,就等后台干完。
  • 最大的坑:Task.Run 里抛的异常装在返回的 Task 里——没人 await,异常静默消失。所以项目里 fire-and-forget 的循环体内自己 try-catch 兜底(AcquisitionPipeline.ConsumeAsync 整个包 try)。
  • 什么时候用:CPU 密集活、要一直转的后台循环。不要用来包"本来就是异步的 IO"(串口/网络读)——那些直接 await。

3. Task.Delay —— 异步的睡

await Task.Delay(500);    // 等 500ms,期间这个线程回线程池干别的
Thread.Sleep(500);        // 这个线程焊死 500ms,什么都干不了
  • Task.Delay(ms, token) 带取消令牌:外部 Cancel() 时它立刻抛 OperationCanceledException,睡到一半也能醒——急停/停止采集能立即生效,靠的就是这个。
  • 易错:写 Task.Delay(500); 忘了 await → 编译警告 CS4014,这一行等于没写(根本没等)。

4. 异步循环 —— 全项目的"心跳"骨架

MC1 模拟卡、R5 消费循环、R4 重连循环,全是同一个骨架:

Task.Run(async () =>
{
    try
    {
        for (var i = 1; i <= steps; i++)
        {
            await Task.Delay(_tickMs, cts.Token);   // ① 等一拍(可被取消打断)
            lock (_gate) _positions[axis] = ...;     // ② 推进一步
            PositionChanged?.Invoke(...);            // ③ 广播
        }
    }
    catch (OperationCanceledException) { /* 急停:就地冻结,不当错误 */ }
});

读法口诀:等一拍、走一步、可打断。await Task.Delay 让出线程(几百个这样的循环同时转,也不占几百个线程);token 让急停毫秒级生效;try-catch 把"取消"当成正常路径而不是崩溃。

5. 闭包捕获 —— C# 和 JS 的 var/let 同款坑

for (var i = 0; i < 3; i++)
{
    tasks.Add(Task.Run(() => Console.WriteLine(i)));   // 打印 3 3 3!
}

C# 的 for 循环变量是"整个循环共享一个变量"——行为等同 JS 的 var(MC1 教训:循环里先 var axis = i; 拷一份再进 lambda)。而 foreach 从 C# 5 起每轮是新变量(等同 let)。规则一句话:lambda 要捕获循环变量,先拷一份局部变量。

自测(全对再翻篇)

  1. UI 线程上 Thread.Sleep(2000) 和 await Task.Delay(2000) 各什么表现?
  2. Task.Run(() => throw new Exception()); 不接返回值,异常去哪了?
  3. 急停为什么能"立即"生效?哪个机制?
  4. CS4014 警告什么意思?
  5. for 循环里 Task.Run 捕获 i,为什么全打印 3?怎么修?
答案(先自己答再看)
  1. 前者界面冻结 2 秒(线程被焊死);后者界面流畅,2 秒后继续(线程期间被释放)。
  2. 装在返回的 Task 里,静默吞掉——必须 await 它,或循环体内部自己 try-catch 兜底。
  3. await Task.Delay(ms, token) 的令牌:Cancel() 一调用,Delay 立刻抛 OperationCanceledException,不用等这一拍睡完。
  4. Task 没被 await——最常见就是 Task.Delay 忘 await,那一行等于没写。
  5. for 的循环变量整个循环共享一个(同 JS var),lambda 执行时循环早结束 i=3;修法:循环内 var copy = i; 捕获副本。
