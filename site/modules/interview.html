面试高频知识点 · 速记卡（手机刷版）

用法：通勤/排队时翻这一页，每条都是上位机 13–15K 面试高频题。先盖住答案自问，再对。配 site/index.html 各模块页做延伸。 心法：面试官不在乎你背多少，在乎你能不能讲清"为什么"——下面每条我都给了"为什么"，这才是 8K→13K 的分水岭。

一、上位机基础

Q1：上位机是什么？和 PLC 的区别？ - 上位机 = 运行在电脑/工控机上的软件，负责监控、采集、存储、展示、下发；PLC 在设备侧做实时控制。上位机通过串口/Modbus/PLC 协议和 PLC 通信。 - 为什么问：确认你懂"上位机在系统里的位置"，不是只会写界面。

Q2：为什么用 WPF 而不是 WinForms？MVVM 是什么？ - WinForms 拖控件、事件里写逻辑，界面和代码耦合；WPF 用 XAML + 数据绑定 + 命令，天然 MVVM：View(界面) / ViewModel(状态与逻辑) / Model(数据) 分离。 - MVVM 好处：可测试（VM 不依赖 UI）、可换肤、团队分工。 - 类比前端：Binding ≈ v-model，Event/Command ≈ addEventListener，ViewModel ≈ 组件的 reactive state。

Q3：.NET / C# 版本怎么选？ - 学用 .NET 8（LTS）：长期支持、岗位主流。本项目用 .NET 8 + WPF，RollForward=Major 可跑在更新的运行时。

二、并发与异步（必考）

Q4：后台采集怎么做到不卡界面？ - UI 线程只负责渲染；采集放后台线程（Task/后台 Timer/Channel 消费者）。数据通过 Channel<T> 批量交给 UI 刷新，不在 UI 线程做重活。 - 本项目：AcquisitionPipeline 用 Channel<T> + Timer 每 200ms 批量出队 → BatchReady 事件 → ViewModel 切回 UI 线程刷新。 - 🎭 拟人段辅助记忆:见 M0_每日讲义_深度版.md#day-7 §Dispatcher + .Result 死锁 + Channel 队列（"前台窗口 + 后厨传菜口"）

Q5：Task 和 Thread 区别？async/await 是什么？ - Thread 是操作系统线程；Task 是"任务"，由线程池调度更轻量。async/await 让异步代码写起来像同步，不阻塞线程。 - 坑：async 方法里别用 .Result/.Wait() 同步阻塞——UI 线程会死锁（本项目 M7 早期就踩过，已改 await）。

Q6：Channel 是什么？为什么用它而不是 ObservableCollection 直接 Add？ - Channel<T> 是高性能生产者-消费者队列，解耦"采样的线程"和"消费的线程"，天然线程安全、背压可控。 - 直接往 ObservableCollection Add 会跨线程异常或卡 UI；Channel 把数据"攒一批"再给 UI，流畅且不崩。 - 🎭 拟人段辅助记忆:见 C#_陷阱_前端转上位机必看_深度版.md#陷阱-2async-void--会议室抢厕所死锁 §会议室抢厕所 + M0 Day 7 §Channel 队列（"前台窗口 + 后厨传菜口"）

三、串口 / 通信（必考）

Q7：RS232 和 RS485 区别？ - 232：点对点、全双工、距离短（~15m）、抗干扰弱。 - 485：差分信号、半双工、可一主多从（总线）、距离长（~1200m）、抗干扰强——工业现场主流。 - 坑：485 半双工要注意收发切换；长距离要终端电阻 + 良好接地，否则数据乱。

Q8：波特率、数据位、停止位、校验位是什么？ - 双方必须一致才能通。常见 9600/8/N/1（9600 波特、8 数据位、无校验、1 停止位）。 - "连不上"第一件事：核对这四项 + 串口号 + 是否被别的软件占用。

Q9：Modbus RTU 和 TCP 区别？ - RTU：跑在串口上，帧 = 从站地址 + 功能码 + 数据 + CRC16；TCP：跑在网口，帧前加 MBAP 头（6 字节），用 CRC 换成 TCP 校验（一般不算 CRC）。 - 功能码：03 读保持寄存器、06 写单个、16(0x10) 写多个、01 读线圈。

Q10：保持寄存器地址偏移怎么算？（高频坑） - 设备手册写 "40001" 是引用地址；协议里功能码 03 的"寄存器地址"通常从 0 开始 → 40001 对应地址 0，40002 对应 1。很多新人直接填 40001 导致读不到。

Q11：粘包 / 半包怎么处理？（重点中的重点） - 串口/TCP 是字节流，不保证"一次发一次收"。可能两帧粘一起，也可能一帧分两次到。 - 解法：定义帧边界 + 缓存重组。本项目 FrameParser：以 0xAA 0x55 头 + 长度域定位一帧；不足一帧先存缓冲区，够了再解析；多帧一次到则循环拆。 - 必须校验 CRC，坏帧丢弃（本项目 5 个串口测试就覆盖了单帧/粘包/半包/坏CRC）。

Q12：PLC（西门子 S7）通信要点？ - 用 S7.Net 连 PLC，读 DB 块（数据块）。注意 DB 块要"非优化访问"才能按偏移读；常见错误 LastErrorCode 要查表。 - 多品牌：三菱用 MC 协议、欧姆龙用 FINS；国内常用 HslCommunication 一把梭多协议。

四、数据与工程量

Q13：工程量转换 / 量程标定是什么？ - 设备给的是原始值（如 0–4095 的 AD 值、或 4–20mA 电流），要换算成工程量（温度℃、压力 MPa）。 - 线性：工程量 = (原始值 - rawMin) / (rawMax - rawMin) * (engMax - engMin) + engMin。4–20mA 时 rawMin 对应 4mA。 - 为什么重要：DAQ 上位机天天做，漏了数据就没有"人话"。

Q14：EF Core 和 ADO.NET / Dapper 区别？企业用什么库？ - EF Core：ORM，写 LINQ 就能存查，开发快；Dapper：轻量 SQL 映射，性能好、可控；ADO.NET 最底层。 - 企业现场 SQL Server / MySQL 最常用（本项目用 SQLite 演示，M12 补了 SQL Server/MySQL + Dapper/ADO.NET）。

五、报警 / 上云 / 控件

Q15：报警为什么要用"回滞（hysteresis）"？ - 阈值在边界抖动时，纯比较会让报警反复触发/消除（"跳变"）。回滞：超过上限才报，要回落到下限以下才解除。本项目 AlarmEngine 已实现。 - 🎭 拟人段辅助记忆:就像空调设定 26℃ — 升到 27℃ 才启动制冷，降到 25℃ 才停机，不会在 26℃ 边界反复开关机磨坏压缩机。

Q16：OPC UA 和 MQTT 区别？ - OPC UA：工业标准、强类型、安全、适合厂内 SCADA/MES 对接。MQTT：物联网轻量发布订阅，适合上云、跨网络。本项目 M7 两者都讲。

Q17：自定义控件 vs UserControl？ - UserControl：组合现有控件，快但难换肤/难复用。自定义控件（继承 Control + Generic.xaml + 依赖属性）：可换肤、可主题、可跨项目。 - 坑：少写 [assembly: ThemeInfo(...)] 控件不报错但一片空白。本项目 GaugeControl/StatusDot 就是正宗写法。 - 🎭 拟人段辅助记忆:UserControl = 拼乐高（快，但只能这模样）；自定义控件 = 自己造乐高零件（难，但能给别人用、能换色）。

六、工程素养（13K→15K 分水岭）

Q18：为什么用接口（IDevice）和依赖注入？ - IDevice 把"设备"抽象成插座；换串口/Modbus/PLC/模拟设备只改组合根一行，UI 和采集层零改动（本项目已用测试证明：换 SerialDevice 不碰 UI）。 - DI（依赖注入）让对象由容器装配，解耦、好测试。

Q19：单元测试怎么测"无界面"的逻辑？ - 用 xunit + Moq：Moq 造假设备（Mock<IDevice>）喂数据，验证管道/存储/报警。本项目 28 个测试全绿，含无界面集成冒烟 + CAN/USB/心跳监测。

Q20：生产环境怎么容错？ - 断线自动重连、失败指数退避重试、采集循环不因为单点异常挂掉。本项目 M9 已落地 Retry 策略。

Q21："连不上"怎么系统排查？（排障能力，面试很看重） - ① 物理层：线/供电/接地/终端电阻；② 配置层：串口号/波特率/站号/IP/端口；③ 协议层：用调试助手/抓包看报文对不对、CRC 对不对；④ 软件层：日志（本项目有 DiagnosticsService + Serilog）、异常堆栈。 - 口诀：先物理、再配置、后协议、最后看日志。

七、简历怎么讲（把项目讲成自己的）

Q22：你的项目架构一句话怎么说？ - "DAQMonitor 是分层工业采集监控系统：Core 领域层（IDevice 抽象 + Channel 并发管道 + 报警引擎 + 报表 + 心跳健康监测）+ UI（WPF/MVVM + 自研控件 + 诊断面板）+ Tests（28 测试）。换设备 UI 零改动，支持串口/Modbus/PLC/CAN/USB-HID 接入。"

Q23：你遇到最难的点是什么？怎么解的？ - 准备一个真实例子：比如"粘包导致数据错乱" → 用帧头+长度+CRC 重组解决；或"UI 卡顿" → 用 Channel 批量刷新解决。能讲清问题→思路→代码→验证就赢。
