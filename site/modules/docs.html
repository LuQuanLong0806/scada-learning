文档能力 · 设计 / 协议 / 操作 / 测试文档（交付硬要求）

为什么有这篇：真实 JD 多次明确要求"设计文档 / 上下位机协议文档 / 操作说明 / 测试报告"。代码能跑还不够，写得出文档 = 能独立负责模块。这是 13→15K 的分水岭之一。 本文给你 4 类文档的模板 + 结合 DAQ Monitor 的范例 + 练习。

一、设计文档（模块设计）

  • 内容：模块职责、对外接口、依赖、关键流程图、异常处理策略。
  • DAQ Monitor 范例：AcquisitionPipeline 设计——输入 IDevice.DataReceived，输出 PointStore + 报警，用 Channel<T> 缓冲，200ms 批量落库。
  • 练习：给 M11 TcpDevice 写一页设计文档（接口 / 帧格式 / 重连策略）。

二、上下位机协议文档

  • 内容：帧格式、命令字、数据域含义、校验、时序、错误码。
  • DAQ Monitor 范例：把 M11 的"长度前缀帧"写成协议文档（头 / 长度 / 命令 / 数据 / 校验 / 尾）。
  • 练习：把 M2 Modbus 读保持寄存器报文整理成协议文档。

三、操作说明（给用户）

  • 内容：怎么装、怎么配串口/IP、怎么看曲线、怎么导出报表、常见报错怎么办。
  • 练习：写 DAQ Monitor 的"5 分钟上手"操作说明。

四、测试报告

  • 内容：测了什么、用例、通过情况、遗留风险。
  • DAQ Monitor 范例：我们的 28 个单测（CompositionSmoke 无界面冒烟 + ReportService 报表聚合 + SerialDeviceTests 串口通信层 6 项 + CanDeviceTests/UsbHidDeviceTests 各 2 + DeviceHealthMonitorTests 2）即报告素材。
  • 练习：把 M9 的测试写成一页测试报告。

📌 跨模块联动

  • 每完成一个模块（M0–M14），顺手产出对应"设计 / 协议 / 操作 / 测试"文档中的相关一项，作品集更完整。
  • 关联：M9 工程素养（测试）、M11 协议帧、M2 Modbus 报文。
