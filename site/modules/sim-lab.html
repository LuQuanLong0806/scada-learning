一、串口 RS232/485(M1)—— 两套方案,按权限选

🎯 协议 30 秒

串口 = 一条按字节排队的双向数据线。双方约定"语速"(波特率)和"帧格式"(数据位/校验/停止位),9600-8-N-1 是最常见出厂默认。RS232 一对一(老设备),RS485 一对多总线(工业主流,差分抗干扰)。

🧰 方案 A:com0com 虚拟串口对(家里推荐)

项 内容
是什么 开源免费的 Windows 虚拟串口驱动,虚拟出 COM3↔COM4 一对,两个程序各开一头,数据互通
下载 SourceForge 官方项目页(GPL 开源)
装法坑 ①要管理员权限装驱动 ②Win11 可能报驱动签名问题 → 用"禁用驱动强制签名"或测试模式装(教程搜"com0com Win11 签名")。所以它适合家里,内网机器基本没戏

怎么试(3 步): 1. 装好后打开 com0com 的 setup 程序,确认有 COM3↔COM4 对(默认就有); 2. 两边各开一个串口助手(如"串口调试助手"任意一款,或 VSCode 插件),COM3 发 hello,COM4 收到 = 物理链路通; 3. 对接 DaqMonitor:把 Bootstrapper 里设备注册换成 new SerialDevice(1, "COM3", new RealSerialChannel("COM3", 9600)),另一个串口助手开 COM4 手发十六进制帧(AA 55 头 + 数据 + CRC),看工程能不能解析出点位。

🧰 方案 B:零安装回环(内网/懒得装驱动)

工程自带 LoopbackSerialChannel:自己发什么就收回什么,纯代码闭环,M1/R4 的测试全用它,一行驱动都不用装。缺点:没有"另一端"的手感——所以它是功能验证工具,不是协议感觉工具;协议感觉用方案 A。

🎤 本协议面试深度

🔴 全部:四参数/232 vs 485/后台线程/粘包。串口是 JD 出现率最高的词,这里没有了解即可。

二、Modbus RTU/TCP(M2 + R4 调库版)—— 实验室的核心,工具最多

🎯 协议 30 秒

工业事实标准。设备数据排成 4 张表(线圈/离散输入/输入寄存器/保持寄存器),上位机用功能码当指令读写;RTU 走串口(帧尾 CRC16),TCP 走网口 502 端口(MBAP 头替代从站地址+CRC)。

🧰 工具选型表(全免费,按推荐度排)

工具 角色 免费性 内网绿色性 下载
FluentModbus 进程内服务器 从站(零安装) ✅ MIT 开源 ✅ 就是个 NuGet 本仓库 R4 附录(沙盒验证版)
diagslave 从站(命令行) ✅ 免费 ✅ 单 exe,完全绿色,内网首选 modbusdriver.com/diagslave
QModMaster 主站(GUI) ✅ 开源 🟡 zip 解压即用 SourceForge
Modbus Poll / Slave 主站/从站(GUI) 🟡 评估版(功能全,有重启提示) 🟡 modbustools.com

实验①:5 分钟起一个真 Modbus TCP 从站(diagslave)

# 家里或内网,解压 diagslave 后:
diagslave -m tcp -a 1 -p 5020        # TCP 从站,站号 1,端口 5020
# 它会打印监听状态;此时任何 Modbus 主站连 127.0.0.1:5020 都能读写它的寄存器
# 全部参数:diagslave -h

用 QModMaster(选 Modbus TCP,填 127.0.0.1:5020,功能码 03,地址 0 起 10 个)读一轮——你现在看到的就是真报文交互。再用 Wireshark 抓 5020 端口,亲眼看 MBAP 头 + 功能码 + 数据,比背十遍帧结构都牢。

实验②:DaqMonitor 调库版直连 diagslave(R4 主路线)

把 R4 调库版 ModbusDevice 的注册改成 simulate: false,host=127.0.0.1、port=5020——工程读到的就是 diagslave 里的真寄存器。然后: 1. QModMaster 往地址 0 写 1234,看工程界面点位跳到 1234; 2. 字节序实验(🔴 必会):让从站给一个 float(占两个寄存器),故意用错的 ByteOrder 解析,看到 0.00003 这种离谱值 → 换对字节序 → 值正常。这一上一下,字节序就从知识变成经历。 3. 配套玩具:仓库自带的 ByteOrderLab(L0 你做过)+ 在线寄存器计算器(搜 "Scadacore Modbus calculator",官网 Tools 区)。

实验③:零安装兜底(进程内从站,内网/CI 用)

// 本仓库《速查·工业通讯调库指南》沙盒验证版(.NET 8 + FluentModbus 5.3.2):
using FluentModbus;
using var server = new ModbusTcpServer();
server.AddUnit(1);                                     // 先注册从站号,再访问缓冲(顺序反了抛 KeyNotFound)
server.Start(new IPEndPoint(IPAddress.Loopback, 15020));
server.GetHoldingRegisterBuffer<short>(1)[0] = 0x1234; // 预置数据:地址 0 = 0x1234
// 主站 Connect 到 127.0.0.1:15020 即可读写 —— 全进程内,零硬件零安装

适合写进单元测试/家里没网时自娱;但日常练手优先 diagslave——它是"外部独立进程",更接近真实设备(你的程序崩了从站还活着,和真实世界一致)。

🎤 本协议面试深度

🔴 全部(4 表/功能码/CRC 手算/字节序/粘包)。Modbus 是 13-15K 面试出现率 100% 的协议,实验室的 3 个实验全部值得做。

三、西门子 S7(M3)—— 概念必会,仿真按档位来

🎯 协议 30 秒

西门子私有协议(ethernet 上走 ISO-on-TCP / S7comm)。上位机不读写"寄存器"而是读写 DB 数据块(PLC 工程师在 TIA 里定义的内存区,如 DB1.DBW0)。C# 侧标准库 S7.Net Plus:new Plc(CpuType.S71200, ip, 0, 1) → Open() → Read("DB1.DBW0")。

🧰 仿真档位(诚实版:免费的都不完美)

档位 方案 花费 适合
🥇 零依赖概念档 不仿真,直接学 S7.Net 用法 + 概念(M3 讲义/R4 附录) 0 赶时间的你,主路线
🥈 软 PLC 档 OpenPLC(开源 PLC runtime,梯形图编程,对上暴露 Modbus TCP 502) 免费 想体验"PLC 那端"怎么编程 → openplcproject.com
🥉 官方仿真档 TIA Portal 试用版 + PLCSIM(西门子官方仿真器) 试用免费,下载几 GB 时间充裕再说;面试口径"用过 PLCSIM"只需概念级
💡 折腾档 snap7 的 Server 模式(Python python-snap7 起进程内 S7 服务,S7.Net 直连) 免费 snap7 SourceForge;要装 Python,内网不友好
💡 平替档 CODESYS 免费版(自带软 PLC 演示,重启限制) 免费 学 IEC 61131-3 标准 PLC 概念

现实建议:你目标是 13-15K 上位机,面试问 S7 主要问"怎么连、怎么读 DB 块、断线怎么办"(概念+S7.Net 代码),极少让你现场组态 TIA。所以 🥇 档为主 + 把 M3 讲义的 S7.Net 代码敲熟,PLCSIM 知道是什么就够了(⚪ 了解即可)。真到现场再用厂里的 PLC。

实验:概念跑通(零安装)

M3 讲义/R4 附录里 PlcDevice(simulate: true) 模式:工程用模拟数据走完 IDevice 全链路——练的是"接入后上层怎么用";真 PLC 交互逻辑(连接参数/DB 地址映射)背 S7.Net 三行:new Plc(CpuType.S71200, ip, 0, 1) / plc.Open() / plc.Read("DB1.DBW0")。

🎤 本协议面试深度

🔴:S7.Net 连接读写流程、DB 块概念。🟡:PLCSIM、1200 vs 300。⚪:TIA 组态、PROFINET 实时性。

四、CAN 总线(M16)—— 了解即可级,一个免费工具备查

🎯 协议 30 秒

汽车/重工领域的广播总线:无主从、按 ID 优先级仲裁(小 ID 先说话)、差分传输。和 485 最大区别:485 一主多从轮询,CAN 谁都可以发,冲突靠仲裁自动让路。

🧰 工具

工具 说明 内网
工程自带 SimulatedCanChannel 零安装,M16 测试全靠它 ✅
Kvaser CanKing 7 免费分析软件,可开虚拟 CAN 通道(免硬件) 🟡 要装 Kvaser 驱动,家里用
PCAN-View PEAK 免费查看器,但实用功能要 PCAN 硬件 ⚪

🎤 本协议面试深度

🟡 会说(是什么/仲裁/和 485 区别/用在哪)。⚪ 帧格式位级细节。不建议在这里花实验时间——JD 里 CAN 出现率低且都写着"优先"。把时间还给 Modbus。

五、OPC UA / MQTT(M7 上云)—— 附赠两个

OPC UA

  • 客户端 UaExpert:免费但要在 Unified Automation 官网注册账号才能下(所以在家下好再拷);能连任何 OPC UA 服务器,看地址空间/订阅数据/看报警。
  • Demo Server:同站 下载页有免费的 ANSI C Demo Server(Windows 版,带模拟数据)——家里下好,双击起服务,UaExpert 连 opc.tcp://localhost:4840 玩。
  • 🎤 深度:🟡 会说(节点概念/订阅 vs 轮询/和 Modbus 的分工:Modbus=设备层,OPC UA=系统层统一接口)。

MQTT

  • Mosquitto broker(mosquitto.org,Windows 版绿色可用)+ MQTTX 客户端(mqttx.app,免费)——本地起 broker、两个窗口互发消息,10 分钟理解主题/QoS。
  • 工程彩蛋:MqttPublisher 默认就配的公共 broker broker.emqx.io:1883——在家里直接能跑真上云(内网不通,内网用 Mosquitto 本地起一个)。
  • 🎤 深度:🔴 QoS 三级一句话区分 + 主题概念;🟡 遗嘱/保留消息。

六、内网离线装箱清单(在家一次备齐,U 盘带走)
