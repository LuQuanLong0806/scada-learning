R0 · DaqMonitor 需求总纲(入职第一天,先看懂全局)

定位:这是项目经理甩给你的《项目需求说明书》。R1-R8 每篇是从它拆出来的迭代任务单。 前置:无(本篇纯读)。预计时长:40 分钟精读 + 建好环境。 产出:看懂系统全貌,知道接下来 8 个迭代各自交付什么、为什么这么拆。

🎯 本篇交付物

读完你能在白纸上画出 DaqMonitor 的数据流架构图,并回答三个面试必问题: 1. 这系统分几层?为什么这么分? 2. 一条温度数据从设备到屏幕,经过哪几站? 3. 100Hz 高频采集,为什么不直接刷 UI/写库?

1. 项目背景(为什么有这个项目)

某注塑/装配车间要上一套数据采集监控系统(DAQ, Data Acquisition): - 车间设备五花八门:串口仪表、Modbus 从站、西门子 PLC、私有 TCP 协议的国产设备; - 车间断网是常态,不能依赖云端,数据必须本地落地; - 值班员 7×24 盯屏:看实时值、看曲线、超限要报警; - 工艺员要查历史、出班次报表;后续还要对接 MES。

你的任务:开发 Windows 上位机 DaqMonitor——.NET 8 + WPF,支持多设备接入、高频采集、报警、历史库、实时可视化。

2. 用户故事(需求从这里来)

# 角色 故事
US-1 值班员 我一打开软件就能看到每个点位的实时值和状态,超限变红报警,不用盯表格
US-2 值班员 曲线要活,温度趋势一眼能看出来,卡顿/白屏不可接受
US-3 工艺员 我要按时间段查历史数据,导出去分析
US-4 设备工程师 加一台 Modbus 设备不能改代码,换个品牌 PLC 最好只改配置
US-5 车间主任 断网/拔网线/设备重启,软件不能崩、不能丢已采数据,恢复了自动重连
US-6 开发自己 改任何模块,跑一遍测试就知道有没有搞坏东西(回归)

一条数据的旅程(面试标准答案): 设备 DataReceived 事件 → 管道 OnPoint 转 SensorPoint → Channel 缓冲 → 定时批量 → BatchReady → {报警引擎判警 / PointStore 双写 / UI 批量刷新曲线}

4. 19 子系统全景 × 迭代拆分(哪篇做哪个)

子系统 内容 迭代 验收
工程骨架 sln 三项目分层 R1 build 0 错 0 警

真实设备 串口/Modbus/TCP/PLC/CAN/HID R4 回环测试绿

为什么这么拆:严格按"数据流向 + 依赖关系"排序——R1 地基、R2 抽象(后面所有设备靠它)、R3 纯逻辑(无 IO 最稳)、R4 挂上真设备、R5 管道串起来、R6 落地数据、R7 组装成系统、R8 长出脸面。每篇只依赖前面篇目,永远可编译可测试。

5. 非功能需求(面试加分项:你不只做功能)

维度 指标
采集能力 ≥ 10 设备 × 100Hz 点位,CPU < 10%,内存稳定无泄漏
UI 流畅 刷新走批量(200ms/批),主线程不卡顿(后台事件→Dispatcher)
可靠性 设备断线自动重连;落库失败不丢内存数据;异常不崩进程
可测试 核心逻辑(协议/报警/管道/存储)100% 可脱离硬件测试
可替换 换设备品牌 = 换一个 IDevice 实现类,上层零改动

7. 里程碑计划(8 个迭代)

迭代 一句话 验收标准
R1 空房子:三项目 + 领域模型 dotnet build 0 错 0 警
R2 第一个"设备":抽象+模拟器 测试:订阅事件收到带时间戳的数据
R3 协议纯逻辑:CRC/三种帧解析 解析测试全绿(含粘包/坏帧)
R4 真设备:串口/Modbus/TCP 回环通道测试全绿
R5 心脏:管道批量 + 报警引擎 批量/回滞/边沿测试全绿
R6 记忆:双写落库 重启进程数据还在
R7 成形:DI 组装 + 诊断 + 重试 冒烟测试一键验全链路
R8 脸面:WPF 主屏 数据滚动/曲线动/报警亮

9. 工程约定(R1-R8 全程有效)

  • 三件套注解:每个代码块前有 📂 文件路径 · namespace / 🔧 NuGet / 💡 类型来源,照抄不迷路。
  • 类型权威:所有类型与前置类型定义一字不差——IDevice 是同步门面(为什么),SensorPoint 是 4 字段 struct(对象初始化器赋值)。
  • 每篇收尾:build + test 全绿才进下一篇;不绿先看报错自己修,30 分钟修不动再看参考实现排错。
  • Git:每完成一个 R 篇 commit 一次,信息写"R{n}: 一句话"——这串 commit 就是你的开发履历。

🎤 面试怎么讲这一篇

"这个项目我按分层架构设计:Core 层放领域逻辑(设备抽象/采集管道/报警/存储),UI 层只做展示,靠 DI 组装。数据链路是事件驱动 + Channel 缓冲 + 批量处理:设备层产生 DataReceived 事件,管道转成 SensorPoint 进 Channel,200ms 一批往下游分发——报警引擎、双写存储、UI 各自订阅。这样把高频采集和慢消费解耦,10 台设备 100Hz 也不卡界面。我是从需求总纲自己拆的 8 个迭代,严格按依赖顺序做,每个迭代都有测试兜底。"
