模块目标

给 SensorPoint 加 EngValue；写出 EngineeringConverter 做量程标定；把 M4 的仓储接口指向 SQL Server / MySQL（改连接串 + 加包，业务代码零改）。

Day 1 — 工程量转换 / 量程标定 🟢

一句话讲清楚

下位机给你的是"原始整数"（如 0~4095 的 ADC 值、或 4-20mA 对应的 6400~32000）。你要用线性公式 工程量 = a × 原始值 + b 把它映射成"真实物理量 + 单位"。

前端类比秒懂

概念 前端类比
量程（下限~上限） 坐标轴 domain(min,max)
线性映射 d3.scaleLinear().domain([0,4095]).range([0,100])
两点标定 已知两组 (x,y) 求斜率截距

分点精讲

① 线性标定公式（🟦）

// 已知：原始 rawLo→工程量 engLo，原始 rawHi→工程量 engHi
double a = (engHi - engLo) / (rawHi - rawLo);
double b = engLo - a * rawLo;
double EngValue(double raw) => a * raw + b;

② 4-20mA 为什么不是 0-20mA（🟦 工程常识） - 4mA 对应量程下限，低于 4mA 即断线/故障——工业标准"活零位"，用电流判断接线是否断。 - 0mA 无法区分"值是 0"还是"线断了"。 ③ 两点标定自动求系数（🟦） - 现场用标准信号源打两个点（如 4mA→0℃、20mA→100℃），代入公式求 a,b，存配置。 ④ 在 SensorPoint 落地

public class SensorPoint {
    public double Raw { get; set; }
    public double EngValue { get; set; }   // 标定后
    public string Unit { get; set; } = "℃";
}

🔬 掰开揉碎：标定为啥用两点法

  • 传感器有零点误差和增益误差，单点校准只能消一个。两点（下限 + 上限）同时消掉偏移(b)和斜率(a)，最稳。
  • 量程反向（如液位越低值越大）只是 a 为负，公式通用。
  • 除零防护：rawHi == rawLo 时公式会崩,真实代码不要在构造函数 throw(产线停机代价太大),给安全默认 1:1 直通 + 日志 WARN,人能继续查 —— 见文末完整代码组装。

⭐ 重点 / 🔥 坑

内容
⭐ 重点 EngValue = a*raw + b，a,b 来自两点标定
🔥 坑 除零(rawHi==rawLo)别 throw,给安全默认 1:1 直通 + WARN;另:Int16 溢出、单位写错(℃ vs ℉)
🔥 坑 4-20mA 断线判定别漏（值 < 4mA 报故障）
🔥 坑 标定时"原始值"和"工程量"单位要一致（别把 mA 当 ℃ 算）

🟢 基础题

ADC 0~4095 对应 0~10MPa，写 EngValue(2048) 应 ≈5MPa。

🟡 进阶题

写 EngineeringConverter 类，构造时传入 (rawLo, rawHi, engLo, engHi)，提供 ToEng(double raw) 和反向 ToRaw(double eng)（下发设定值用，见 M3 写 PLC）。

🔴 挑战题

实现"量程反向"场景：液位 0~5m 对应原始值 4095~0（a 为负）。用同一个 EngineeringConverter 测 ToEng(2048) 应为约 2.5m，验证公式通用性。

✅ 答案（基础题） a = 10/4095，b = 0，EngValue(2048) = 10×2048/4095 ≈ 5.003。

🏗️ 项目任务：在 SensorPoint 加 EngValue/Unit，TcpDevice/SimulatedDevice 采集时填充。DAQ Monitor 点表里同时显示"原始值 / 工程量"。

🎓 工控导师说：标定系数千万别写死在代码里！我见过一台设备换传感器后，工程师忘了改 a、b 常量，显示温度整体偏了 8℃，产线工艺全错。系数必须来自配置 / 数据库 / 设备描述文件，换硬件只改配置不动代码。

💼 职业建议：工程量转换是"工程师基本功"。面试官看你代码里 value * 0.1 直接当温度，就知道你没理解标定；写成 EngineeringConverter 可配置，才是企业写法。

🔬 掰开揉碎：传感器非线性标定（线性公式的边界）

上面讲的 y = k*x + b 线性公式覆盖 80% 场景(ADC、4-20mA、压力变送器),但下面这两类传感器本身是非线性的,用线性公式会出错:

  • 热电偶(TC):热电势 ↔ 温度是非线性曲线,K 型在 0℃ 时 ~39 μV/℃,1000℃ 时 ~41 μV/℃,直接当线性算偏差能到几度。
  • 热电阻(RTD,PT100/PT1000):电阻 ↔ 温度也是非线性,100℃ 时约 138.5Ω,200℃ 时约 175.8Ω,不是等距。

前端类比:线性公式像 CSS linear-gradient,只能描述直线;非线性传感器像贝塞尔曲线,需要更复杂的映射函数。处理方案有两种:

① 查表法(Lookup Table)—— 厂家给的标准表 + 二分查找 + 线性插值(最常用,够精度)

public static class RtdLookup
{
    // PT100 标准表(节选,真实项目用整张 IEC 60751 表)
    private static readonly (double R, double T)[] Table =
    {
        (100.0, 0), (103.9, 10), (107.8, 20), (111.7, 30),
        (115.5, 40), (119.4, 50), (123.2, 60), (127.1, 70),
        (130.9, 80), (134.7, 90), (138.5, 100)
    };

    public static double OhmToCelsius(double r)
    {
        // 1. 边界短路
        if (r <= Table[0].R) return Table[0].T;
        if (r >= Table[^1].R) return Table[^1].T;

        // 2. 二分查找找到 r 落在哪两个点之间
        int lo = 0, hi = Table.Length - 1;
        while (hi - lo > 1)
        {
            int mid = (lo + hi) >> 1;
            if (Table[mid].R <= r) lo = mid; else hi = mid;
        }

        // 3. 线性插值(两点之间近似为直线 —— 表越密越准)
        var (r0, t0) = Table[lo];
        var (r1, t1) = Table[hi];
        return t0 + (r - r0) * (t1 - t0) / (r1 - r0);
    }
}
// 用法:double temp = RtdLookup.OhmToCelsius(119.4);  // → 50.0℃

优点:精度可控(表越密越准)、可校准单点偏移、对 CPU 友好(只有比较和一次除法)。坑:表必须按 R 升序排好,二分才能用。

② 多项式拟合(Callendar-Van Dusen 公式)—— RTD 国际标准

R(t) = R0 * (1 + A*t + B*t²)           // t ≥ 0℃ 的简化形式
// R0=100(PT100), A=3.9083e-3, B=-5.775e-7 (IEC 60751 标准常数)

直接用公式反解 t(求二次方程),精度比查表更高但代码复杂。建议:除非客户明确要求高精度,否则用查表法 —— 维护方便、足够工业级。

何时需要非线性标定:面试时被问"PT100 怎么换算温度",答"查表 + 线性插值"或"Callendar-Van Dusen 多项式"就是工程师水平的体现;只会线性公式 = 没踩过传感器的坑。

Day 2 — 企业数据库 SQL Server / MySQL（换库零改业务）🟡

一句话讲清楚

M4 用 SQLite 是"轻量入门"。真实工厂 90% 用 SQL Server（微软系上位机标配）或 MySQL。好消息：EF Core 是面向提供程序的，换库 = 换连接串 + 加一个 NuGet 包，业务代码一行不动。

前端类比秒懂

换库动作 前端类比
UseSqlServer 换 UseMySql 把 Prisma 的 provider 从 postgres 改成 mysql
业务代码零改 ORM 屏蔽差异，Repository 不变

分点精讲

① EF Core 换提供程序（🟧）

<!-- 把 M4 的 Sqlite 包换成 -->
<PackageReference Include="Microsoft.EntityFrameworkCore.SqlServer" />

// Program / Bootstrapper 里只改这一行：
options.UseSqlServer("Server=.;Database=DAQ;Trusted_Connection=true;");
// 原来 UseSqlite(...) 换成 UseSqlServer(...) 即可

② Dapper 轻量批量写（🟧，高频点位写入更快）

using Dapper;
await using var conn = new SqlConnection(cs);
await conn.ExecuteAsync(
  "INSERT INTO Points(Chan,Raw,Eng,Unit,Ts) VALUES(@Chan,@Raw,@Eng,@Unit,@Ts)",
  points);   // points 是 IEnumerable<SensorPoint>

③ 三选一：EF Core（ORM 方便）→ Dapper（高频写快、SQL 可控）→ ADO.NET SqlBulkCopy（海量批量最快）。

④ 连接串安全管理 —— 生产环境绝不硬编码（🟦，面试加分项） 上面演示里的 "Server=.;Database=DAQ;..." 只是教学用,真实生产代码严禁把密码硬编码进 .cs(进 Git = 进全公司眼睛 + 历史泄露)。三层做法按环境选: - 开发:appsettings.json + User Secrets(dotnet user-secrets set "ConnectionStrings:DAQ" "Server=.;Database=DAQ;User=sa;Password=xxx")—— 密码存本机用户目录,不进 Git。 - 测试/生产(自托管):环境变量 ConnectionStrings__DAQ(双下划线 = 配置路径分隔),Docker/K8s 直接注入。 - 云端:Azure Key Vault / AWS Secrets Manager,程序启动时拉密钥。

// appsettings.json(只放非敏感的 host/db 名,密码走 User Secrets/环境变量/Key Vault)
{
  "ConnectionStrings": {
    "DAQ": "Server=prod-sql;Database=DAQ;User=sa;Password=${DB_PWD};"
  }
}

// Program.cs / Bootstrapper —— 通过 IConfiguration 读连接串(配合 M9 DI)
var cs = builder.Configuration.GetConnectionString("DAQ")
    ?? throw new InvalidOperationException("缺少 DAQ 连接串配置");
services.AddDbContextFactory<AppDb>(o => o.UseSqlServer(cs));

前端类比:像前端绝不会把 API token 写进 config.js 提交到 Git,要走 .env + process.env.REACT_APP_TOKEN;C# 这边对应的 IConfiguration + 环境变量,思路完全一致。

🔬 掰开揉碎：为什么 SQL Server 是上位机标配

  • 工厂 IT 基础设施清一色 Windows + SQL Server，运维、备份、权限都现成。
  • 和 C#/.NET 同属微软生态，部署、驱动、文档一条龙，坑最少。
  • MySQL 在跨平台/成本敏感场景常见；会换提供程序 = 不挑客户环境。

⭐ 重点 / 🔥 坑

内容
⭐ 重点 EF Core 面向提供程序，换库 = 换连接串 + 加包
🔥 坑 不同库的类型映射差异（如 datetime/uniqueidentifier）
🔥 坑 连接串里密码别硬编码,走 appsettings.json + User Secrets(开发)/ 环境变量(生产)/ Key Vault(云端)
🔥 坑 高频写用攒批（M4 Day1 的 10 倍性能差）或 Dapper/SqlBulkCopy

🟢 基础题

把 M4 的 AppDb 从 UseSqlite 改成 UseSqlServer（仅改一行），并在本机 SQL Server LocalDB 建库跑通一条插入。

🟡 进阶题

用 Dapper 把"最近 1 秒采集的 100 个点"一次 ExecuteAsync 批量插入，对比 M4 的逐条 SaveChanges 体会速度差。

🔴 挑战题

写一段数据库无关代码：依赖 IHistoryRepository 接口，运行时按配置决定用 SQLite / SQL Server / MySQL 实现（M9 的 DI 注册切换）——验证"业务代码零改"。

✅ 答案（基础题）

protected override void OnConfiguring(DbContextOptionsBuilder b)
    => b.UseSqlServer("Server=(localdb)\\mssqllocaldb;Database=DAQ;Trusted_Connection=true;");

🏗️ 项目任务：把 DAQ Monitor 的 HistoryRepository 背后 DbContext 指向 SQL Server（或 MySQL），DAQ Monitor 历史库从 SQLite 平滑迁移，UI/报表零改动。

🎓 工控导师说：客户现场最怕"你的程序依赖某个特定数据库，结果他们 IT 标准用的是另一个"。凡是把数据访问藏在 Repository 接口后面、用 DI 注入实现的项目，到哪都能活。反之把 UseSqlite 写死在业务里，换库就是重写。

💼 职业建议：JD 几乎都写"熟悉 SQL Server / MySQL 至少一种"。你能讲"EF Core 面向提供程序、换库只改连接串、业务零改 + 高频写用 Dapper 攒批"，面试官立刻放心——你懂企业数据库工程。

🧩 完整代码组装（EngineeringConverter 可直接抄进工程）

// DaqMonitor.Core/Models/EngineeringConverter.cs
public class EngineeringConverter
{
    public double RawLo { get; }
    public double RawHi { get; }
    public double EngLo { get; }
    public double EngHi { get; }
    private readonly double _scale;   // 缓存标定斜率,避免每次 ToEng 都除一次
    private readonly double _offset;  // 缓存标定截距

    public EngineeringConverter(double rawLo, double rawHi, double engLo, double engHi)
    {
        if (Math.Abs(rawHi - rawLo) < 1e-9)
        {
            // 量程为 0,给安全默认(1:1 直通),不抛异常 —— 现场调试时不该让程序崩
            // 真实做法:这里 + 日志 WARN,让人能继续查问题(见 Day1 末尾"工程导师说")
            RawLo = 0; RawHi = 1; EngLo = 0; EngHi = 1; _scale = 1; _offset = 0;
            return;
        }
        RawLo = rawLo; RawHi = rawHi; EngLo = engLo; EngHi = engHi;
        _scale  = (engHi - engLo) / (rawHi - rawLo);   // 预计算,避免每次都除
        _offset = engLo - _scale * rawLo;
    }
    public double ToEng(double raw) => _scale * raw + _offset;
    public double ToRaw(double eng) => (eng - _offset) / _scale;   // 反向:下发设定值
}
// 用法：var c = new EngineeringConverter(6400, 32000, 0, 100); // 4-20mA → 0~100℃
//       double temp = c.ToEng(rawFromDevice);

为什么不在构造函数 throw:工控现场调试时如果工程师量程填错(rawHi == rawLo),程序直接崩 = 整条产线停。给安全默认 1:1 直通,在日志里 WARN 一下,人能继续查问题、设备照常跑(只是显示的工程量不对)。前端类比:像表单校验失败时不该白屏,要给 fallback UI + 红字提示,而不是把整个页面 crash 掉。 M4 的 HistoryRepository 仅把 UseSqlite 换成 UseSqlServer/UseMySql 即可接企业库（见 Day2 ①）。
