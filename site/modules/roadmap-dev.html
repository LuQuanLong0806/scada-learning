DAQMonitor 项目开发全景 · 每一步是什么 / 为什么 / 现成 vs 自研

这份文档帮你一眼看懂企业级上位机是怎么长出来的。它不是按"模块号 M0–M14"排的，而是按项目真实成长的顺序排——你学的时候也是这个顺序：先打地基，再一层层往上加能力。

图例（和我们讲义一致）： - 🟦 C# 语法：语言自带，不装包 - 🟩 .NET 类库（BCL）：随 .NET 安装，官方自带 - 🟧 第三方 NuGet：免费开源，需 dotnet add package - 🛠️ 自己开发：业务逻辑 / 架构 / 控件 / 协议解析——这是你"学会写上位机"的真正价值所在

0. 一句话建立心智模型

DAQMonitor = 三层架构 + 一条数据主线 + 三大支柱
├─ 三层架构：Core(业务核心) · UI(界面) · Tests(测试)   ← 分层是为了"可替换、可测试"
├─ 一条数据主线：设备 → 管道 → 存储/报警 → 界面/库/云   ← 数据永远单向流动
└─ 三大支柱：① 面向接口(换设备不动UI) ② 并发采集(后台不卡界面) ③ 工程素养(测试/DI/容错)

最关键的认知：这个项目里"能直接用的"都是地基和工具（语言、框架、通信库、图表库、数据库），"必须自己写的"才是你的本事（设备抽象、采集管道、报警逻辑、业务控件、协议解析、组合根装配）。下面逐步拆开。

1. 开发步骤全景表（按真实顺序）

# 这一步做什么 为什么必须这么做 直接用（现成） 自己开发（自研）
1 脚手架 + 分层（Core/UI/Tests 三工程） 分层后"换设备不动 UI、换数据库不动采集"，且每层可独立测试 🟦 项目模板 / 🟩 MSBuild 🛠️ 三层目录划分、引用关系、命名约定
2 领域模型 SensorPoint（点位/数值/时间/状态） 全链路共用一个"数据点"结构，下游不用反复转换 🟦 record/class 🛠️ 字段设计（含 Timestamp 贯穿事件链）
3 设备抽象 IDevice + DeviceBase 界面只认接口，不关心串口/网口/PLC——换硬件 UI 零改动（面向接口的核心） 🟦 interface/event/abstract 🛠️ 接口方法设计（Connect/Read/Write/DataReceived）
4 模拟设备 SimulatedDevice 没有真实硬件也能跑通整条链路，边学边演示 🟩 Task/定时器/Random 🛠️ 后台线程按周期产点、~10% 越界触发报警
5 采集管道 AcquisitionPipeline 后台线程收数据 → Channel<T> 缓冲 → 200ms 定时批量出队，界面永不卡顿、无内存泄漏 🟩 System.Threading.Channels 🛠️ 统一采集架构（注册设备/批量出队/回调 UI）
6 存储 PointStore 最新值缓存 + 历史序列，报警/曲线/报表都从它取 🟦 ConcurrentDictionary/List 🛠️ 线程安全的最新值表 + 历史循环缓冲
7 报警引擎 AlarmEngine（带回滞） 阈值判断 + 回滞(Hysteresis)防抖动（到 101 报、回到 99 才解除，不是 100 反复跳） 🟦 事件/字典 🛠️ 规则模型、越界判定、上升沿/下降沿（报警+恢复）
8 组合根 Bootstrapper（DI 装配） 把所有服务"焊"在一起，放在 Core 不在 UI——测试/未来服务端都能复用同一套装配 🟧 Microsoft.Extensions.DependencyInjection 🛠️ 注册顺序、生命周期(Singleton)、预置报警规则
9 界面 MainWindow + MainViewModel（MVVM） MVVM 让"数据绑定"代替"手动刷新控件"，企业级标配 🟩 WPF / 🟧 CommunityToolkit.Mvvm 思路 🛠️ MainViewModel 订阅管道事件、命令(Start/Stop/导出)、_levels 同步报警级别
10 自定义控件 GaugeControl/StatusDot 仪表盘/状态灯是上位机"脸面"，自绘才能满足工业审美与复用 🟩 WPF Control/DependencyProperty 🛠️ Generic.xaml+ThemeInfo、Level 属性接报警变色
11 持久化 EF Core + SQLite 历史数据落库才能查/导出/做报表 🟧 EF Core/SQLite（均免费） 🛠️ DbContext、实体映射、迁移、按时间查询
12 实时可视化 LiveCharts 把点变成动态曲线/仪表盘，人才看得懂 🟧 LiveCharts（免费） 🛠️ 把 PointStore 数据接进图表系列的绑定逻辑
13 报表 ReportService + ClosedXML 把"数据库+曲线+报警"收口成企业交付物（Excel/PDF） 🟧 ClosedXML(MIT)/QuestPDF 🛠️ ReportService 聚合(min/max/avg，纯逻辑可单测)
14 诊断/调试 DiagnosticsService + 面板 工业现场 80% 时间在"为什么没数据/连不上"——内置诊断面板 = 排查力 🟧 Serilog（结构化日志，免费） 🛠️ 采集统计(采样数/报警数/批次耗时) + 环形日志(≤200条) + 诊断 Tab
15 通信层 M1–M3（串口/Modbus/PLC） 真实设备靠协议对接，这是岗位"必会" 🟧 System.IO.Ports(BCL)/NModbus/S7.Net/HslCommunication 🛠️ 把串口/Modbus/PLC 实现成 IDevice 的具体子类（接步骤 3 的接口）。✅ 串口已落地：SerialDevice + ISerialChannel/RealSerialChannel/LoopbackSerialChannel（零硬件内存回环，没串口也能跑），含 FrameParser.Build 双向建帧 + CRC 校验，21 测试中 5 个串口实测（单帧/粘包/半包/坏CRC/管道集成）。Modbus/PLC 设备类待 M2/M3 落地。
16 上云 M7（OPC UA / MQTT） 对接 SCADA/云端，15K 加分 🟧 OPCFoundation UA/MQTTnet（免费） 🛠️ 发布订阅桥接、断线重连策略
17 工程量转换 M12 原始值(0–4095 / 4–20mA) → 工程量(℃/MPa)，DAQ 基本功 — 🛠️ 线性标定公式、多量程、反向下发、查表法
18 容错重试 Resilience/Retry 网络抖动/设备掉线时指数退避重连，生产环境必备 🟦 Task/CancellationToken 🛠️ 指数退避算法封装
19 单元测试 xunit + Moq 证明代码对、重构不怕改坏——13K→15K 分水岭 🟧 xunit/Moq（免费） 🛠️ 用 Moq 造假设备验证管道、28 个测试全绿（含 CAN/USB/心跳监测）
20 协议解析 Protocol/Crc16/FrameParser 串口/TCP 私有帧要自己拆包、算校验 🟦 位运算 🛠️ CRC16 反射算法、半包/粘包处理、帧结构解析

3. 快速看懂这个项目的"阅读顺序"

别从 Main() 开始读，按数据主线读最快：

  1. 先看 IDevice（Devices/IDevice.cs） —— 它是整个系统的"插座标准"：所有设备（模拟/串口/PLC）都插这个口。
  2. 再看 Bootstrapper（AppServices/Bootstrapper.cs） —— 它是"装配图"：new SimulatedDevice() 挂到 AcquisitionPipeline，报警规则预置好。换真实设备只要改这一行。
  3. 然后 AcquisitionPipeline —— 数据怎么从设备流进来、怎么批量出去。
  4. MainViewModel + MainWindow —— 数据怎么进界面、控件怎么绑。
  5. 最后看 GaugeControl/AlarmEngine/DiagnosticsService —— 这些是"加分项"：控件自绘、报警逻辑、诊断面板。

一句话：IDevice 定义标准 → Bootstrapper 装配 → Pipeline 流动 → ViewModel/UI 展示 → 自研控件/报警/诊断/报表 是长在这条主线上的"器官"。

4. 你学的时候，每一步该"抄"什么、该"写"什么

学习动作 抄（直接用） 写（自己动手）
搭工程 复制三层 csproj 模板 决定命名、引用谁
接设备 装 NModbus/S7.Net 写 XxxDevice : DeviceBase 把协议套进 IDevice
做界面 用 WPF / HandyControl 写 ViewModel 业务逻辑、写自定义控件
存数据 用 EF Core 设计实体、写查询/聚合
出报表 用 ClosedXML 写 ReportService 聚合逻辑
保质量 用 xunit/Moq 写测试用例、用 Mock 造假设备
排故障 用 Serilog 设计诊断面板要展示哪些指标

核心心法："数据来源与绘制分离、原始值与工程量分离，换场景只改配置不改动控件"——这就是企业级复用的精髓，也是你面试时能讲清楚、和 8K 岗拉开差距的关键。

📌 温故知新 / 跨模块联动

  • 本表是 M0–M14 全部模块在项目里的"落地位置"：想看某知识点在代码里长什么样，按 # 列对应模块去翻 DAQMonitor/src。
  • M0 打的三层+接口+并发，是后面所有模块的"插槽"；M9 的 DI/测试/容错让架构可装配可验证；M14 的控件已提前种进项目（步骤 10），不是等学完才补。
  • 调试能力（步骤 14）不是单独一章，而是贯穿每一步——DiagnosticsService 统计采样数/报警数/批次耗时，帮你立刻看出"哪一步没跑起来"。
