项目三 · CommLab 工业协议调试助手（规划与路线）

定位：DAQMonitor 是"把数据收上来做监控系统"，CommLab 是"帮工程师把设备联调通的调试工具"。 一个偏 系统 / 产品，一个偏 工具 / 效率——两份作品覆盖上位机两大典型岗位方向，互相佐证你"既会做系统、又懂协议与调试"。 本文件是路线规划（阶段清单 + 技术栈 + 复用关系）。等你启动它时，我会把每个阶段扩写成和 M0–M14 同标准的「深度版」动手讲义。

🎯 为什么加这一份（面试价值）

作品 体现的能力 面试官看到的是什么
DAQMonitor（主项目·深度） 架构设计、Channel<T> 并发采集、全栈（采集/存储/可视化/报警/报表/上云）、工程素养（DI/单测/容错） "能独立做一个完整工业系统"
CommLab（第 2 作品·广度） 协议深度（Modbus/串口帧/CRC）、调试排查能力、工具化思维、UI 交互细节 "真懂协议、能独立联调排障"

两份一摆，面试官无法说"只会做一种"。而且 CommLab 和 DAQMonitor 是同一套协议功底（都用 IDevice/SerialDevice/FrameParser），一正一反互相印证——你说"我懂 Modbus"，作品里既有"系统里用 Modbus 收数"又有"工具里用 Modbus 联调"，可信度直接拉满。

🔗 与 DAQMonitor 的复用关系（所以成本低）

类别 内容 说明
🟩 直接复用 IDevice / DeviceBase、ISerialChannel / RealSerialChannel / LoopbackSerialChannel 通信底座一模一样，换层皮就是新工具
🟩 直接复用 FrameParser + Crc16、Serilog 诊断、HandyControl / 自定义控件 协议解析与 UI 资产复用
🛠️ 需自研（新价值点） 报文编辑器（Hex 输入/解析预览）、主站/从站模拟引擎、抓包 RingBuffer + 时间轴回放、多协议切换状态机、报文模板库 这些 DAQMonitor 没有，正是"广度"的体现

结论：CommLab 不是从零，是在你已经会的东西上"换用途长新器官"。预估工程量 ≈ DAQMonitor 的 2–3 个模块，远低于重开一个系统。

🧰 技术栈（全程免费开源）

  • 通信：System.IO.Ports（串口）、NModbus（Modbus RTU/TCP）、S7.Net（顺带支持 PLC 直连调试）
  • 可视化：LiveCharts（报文时序/轮询曲线）、HandyControl（工业风控件）
  • 诊断/导出：Serilog（操作日志）、ClosedXML（抓包日志导出 Excel）
  • 架构：WPF + MVVM + IDevice 抽象（和主项目同一套思想）

🗺️ 路线（4 个阶段，建议 DAQMonitor 走到 M6 后启动）

阶段 A · 串口透传终端（复用 SerialDevice）

  • 做什么：十六进制/ASCII 双模式收发、时间戳、自动滚动、发送历史、快捷指令按钮。
  • 为什么：先把"串口通道"用熟，等价于把 DAQMonitor 的通信层做成"人能直接对话"的版本。
  • 现成 vs 自研：🟩 RealSerialChannel；🛠️ 收发 UI、Hex 解析、快捷指令。
  • 看懂 SerialDevice 如何被复用 [ ] 写出 Hex 收发界面

阶段 B · Modbus 帧构造器 + 自动 CRC（封装 NModbus）

  • 做什么：选功能码(01/03/05/06/15/16)→ 自动组帧 + CRC 校验 → 一键读/写保持寄存器/线圈；响应解析成表格。
  • 为什么：这是上位机联调最高频动作，做出来就是"即战力工具"。
  • 现成 vs 自研：🟧 NModbus；🛠️ 帧构造 UI、功能码模板、响应结构化展示。
  • 用 NModbus 写出读 4x 寄存器 [ ] 手工组帧并验证 CRC 与工具一致

阶段 C · 模拟从站 + 抓包回放（新能力）

  • 做什么：模拟一个 Modbus 从站（按脚本响应读/写）、把通信过程抓成带时间戳的报文流、支持"时间轴回放"排查间歇性故障。
  • 为什么：现场最头疼的就是"偶发错"，回放能力是排障神器，也是面试谈"调试能力"的硬素材。
  • 现成 vs 自研：🟩 NModbus 从站模式；🛠️ 从站脚本引擎、RingBuffer 抓包、时间轴回放控件。
  • 起一个模拟从站被主站读 [ ] 抓 100 条报文并回放

阶段 D · 协议切换 + 模板库 + 导出（收口）

  • 做什么：ASCII/RTU/TCP 一键切换状态机、常用报文模板库（可保存/载入）、抓包日志导出 Excel。
  • 为什么：从"能用的工具"变成"可交付的产品"，体现工程收口能力。
  • 现成 vs 自研：🟧 ClosedXML；🛠️ 协议状态机、模板持久化。
  • 切 RTU/TCP 都能通 [ ] 导出一次抓包日志

📝 简历描述草稿（两份一起投时用语）

CommLab · 工业协议调试助手（C# / WPF） 支持串口与 Modbus-TCP 报文构造、CRC 自动校验、主站/从站模拟、报文抓包与时间轴回放，用于设备联调与故障排查；复用自研 IDevice 抽象与帧解析内核，导出日志支持 Excel。

DAQMonitor · 工业数据采集监控系统（C# / WPF / .NET 8） 多设备可插拔采集（串口/Modbus/PLC/CAN/USB-HID）、Channel<T> 并发管道、实时可视化、历史库(EF Core)、报警引擎、OPC UA/MQTT 上云、报表导出、自研控件与诊断面板、心跳健康监测；28 项单元测试全绿。

⏱️ 学习顺序建议（不挤占现在）

  1. 现在：专注 DAQMonitor M0 → M10 主线，把系统级能力打牢（这是主项目，优先级最高）。
  2. DAQMonitor 走到 M6（通信/报警已落地）后：启动 CommLab 阶段 A–B——此时你的协议功底已具备，做起来很快。
  3. 求职前：两份作品都成型，互补投递；面试时一份讲"系统架构"、一份讲"协议与调试"，覆盖度拉满。

💡 心法同主项目：数据来源与绘制分离、原始值与工程量分离，换场景只改配置不改动控件——CommLab 的"报文编辑器"和 DAQMonitor 的"GaugeControl"是同一个思想的两种面孔。
