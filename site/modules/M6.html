Day 1 — 报警引擎 + 事件总线 🟡

一句话讲清楚

报警引擎 = 一组"规则"，每条规则说"点位 X 超过 Y 就报警 Z 级"；数据流过时逐条匹配，命中就发事件通知 UI / 写日志。

分点精讲

① 规则模型 + 引擎（🟦）

📂 两个文件:DaqMonitor.Core/Alarms/AlarmRule.cs + AlarmEngine.cs · namespace DaqMonitor.Core.Alarms 🔧 无 NuGet(纯 C# 逻辑) 💡 用到 SensorPoint / AlarmLevel / AlarmEvent(都在 前置类型定义);AlarmRule 与参考工程一字不差,AlarmEngine 是教学简版(工程完整版含回滞+边沿触发,见下「掰开揉碎」和前置类型定义 §四)

// DaqMonitor.Core/Alarms/AlarmRule.cs
namespace DaqMonitor.Core.Alarms;

using DaqMonitor.Core.Models;

public class AlarmRule
{
    public int PointId { get; set; }
    public double Threshold { get; set; }
    public double Hysteresis { get; set; }      // 回滞带(下面"回滞"小节详解),生产必配
    public AlarmLevel Level { get; set; }      // M0 Day2 的 enum
    public bool IsHigh { get; set; } = true;   // true: 超上限报警；false: 低于下限
}

// DaqMonitor.Core/Alarms/AlarmEngine.cs
namespace DaqMonitor.Core.Alarms;

using DaqMonitor.Core.Models;

public class AlarmEngine
{
    private readonly List<AlarmRule> _rules = new();
    public event EventHandler<AlarmEvent>? AlarmTriggered;

    public void Add(AlarmRule r) => _rules.Add(r);

    public void Evaluate(SensorPoint p)
    {
        foreach (var r in _rules)
            if (r.PointId == p.Id && (r.IsHigh ? p.Value > r.Threshold : p.Value < r.Threshold))
                // ⚠️ AlarmEvent 用 init 属性,可用对象初始化器;Timestamp 走默认值 DateTime.Now
                AlarmTriggered?.Invoke(this, new AlarmEvent
                {
                    PointId = p.Id,
                    Level = r.Level,
                    Value = p.Value
                });
    }
}

② 接到数据流（呼应 M0 Day 6）

💡 DataReceived 的事件参数 e 是 DataEventArgs(PointId/Value/Timestamp),而 Evaluate 吃的是 SensorPoint — 中间要做一次转换,e.Timestamp 必须抄过来(否则落 default(DateTime) = 0001-01-01)。 真实工程里这层转换由 AcquisitionPipeline.OnPoint 统一做,报警引擎订阅的是管道的 BatchReady 批量事件(M9 架构);下面给"直接订阅设备事件"的教学版。

device.DataReceived += (s, e) =>
{
    var p = new SensorPoint { Id = e.PointId, Value = e.Value, Timestamp = e.Timestamp };
    engine.Evaluate(p);          // 转成 SensorPoint 再送判警
};
engine.AlarmTriggered += (s, a) => Console.WriteLine($"⚠ 点位{a.PointId} 报警{a.Level} 值={a.Value}");

// 工程版(M9):订阅管道批量事件,一批一起判,不用自己转
// pipeline.BatchReady += (s, batch) => { foreach (var p in batch) engine.Evaluate(p); };

🔬 掰开揉碎：回滞（Hysteresis）—— 生产报警的「必做题」

讲义之前把回滞标成「可选进阶」，但本项目的 AlarmEngine.cs 真实代码已经用了它，你必须会写，否则你写不出和项目一致的实现。 - 问题场景：阈值 100，真实温度在 99↔101 之间抖动（工业常态，噪声导致）。没有回滞时：101 报警 → 100 不报 → 101 又报 → 100 又不报……一秒内刷几十次「报警/恢复」，这就是报警风暴，值班人直接无视。 - 回滞解法：设两个阈值——触发 100 / 恢复 95。只有「超过 100」才报；之后要「降到 95 以下」才算恢复，中间抖动区间（95~100）保持原状态不变。类比：空调设 26°，到 26° 停机，但回到 28° 才重启，避免频繁启停。 - 本项目 AlarmRule 的真实字段（代码里就有）： csharp public double Threshold { get; set; } // 触发阈值（如 100） public double Hysteresis { get; set; } // 回滞带（如 5 → 恢复阈值 = 95） public bool IsHigh { get; set; } = true; // true: 超上限报警；false: 低于下限报警 - 边沿触发（本项目也做了）：即使值持续超阈值，也只报一次（记录「已报警」状态，恢复前不再重复触发），这就是之前 M9 测试 Evaluate_FiresOnlyOnRisingEdge 验证的行为——避免「持续超阈还每秒刷屏」。

⚠️ 重点 & 易踩坑

项 说明
⭐ 规则与数据分离 规则放配置，不改代码就能加报警点
⭐ 防抖 / 回滞 值在阈值附近抖动会狂报警，用"恢复区间"避免（生产必做，见上「掰开揉碎」）
🔥 报警风暴 一秒内上千点超限，要限流/聚合再通知
🔥 跨线程 引擎在后台线程跑，通知 UI 要 Dispatcher

🟢 基础题

写 AlarmRule 与 AlarmEngine，给点位 3 设阈值 100（超上限 Critical），喂几个点验证是否触发。

🟡 进阶题

给点位 3 加回滞：Threshold=100, Hysteresis=5（恢复阈值 95）。喂序列 99→101→100→96→94，验证"101 报、100 不恢复、94 才恢复"，理解回滞如何消灭报警风暴。

🔴 挑战题

把报警引擎接入 M9 的 AcquisitionPipeline.BatchReady：订阅批量事件，把每批点送进 Evaluate，并在 AlarmTriggered 里写一条 Serilog 日志（而非 Console.WriteLine）。

✅ 答案（进阶题要点）

var r = new AlarmRule { PointId = 3, Threshold = 100, Hysteresis = 5, Level = AlarmLevel.Critical, IsHigh = true };
// 99 → 不报；101 → 报(Critical)；100 → 仍报(在回滞带内保持)；96 → 仍报；94 → 恢复

🏗️ 项目任务：DAQ Monitor 加 Alarm/AlarmEngine.cs，启动时从配置加载规则；DataReceived 里 Evaluate；报警时 UI 闪烁 + 写日志。报警能力达标。

🎓 工控导师说：回滞是工业报警的"必做题"不是"选修"。我见过没回滞的系统，温度在阈值上下抖，一秒弹 30 次报警框，操作员直接把报警静音——结果真超温时没人看见。回滞 + 边沿触发（只报一次）是保命设计。

💼 职业建议：面试被问"怎么处理报警"，能讲出"回滞避免风暴 + 边沿触发避免刷屏 + 落库统计"三点，直接证明你写过生产级报警系统，不是玩具。

Day 2 — Serilog 结构化日志 🟡

一句话讲清楚

Serilog 把"发生了什么"按级别（Info/Warn/Error）结构化写进文件，出问题能回放 —— 企业级必不可少的"黑匣子"。

分点精讲

① 配置 + 写日志（🟧）

🔧 必装 NuGet(在 src/DaqMonitor.Core/ 目录执行): bash cd src/DaqMonitor.Core dotnet add package Serilog # 核心库 dotnet add package Serilog.Sinks.File # 文件 sink(按天滚动) dotnet add package Serilog.Sinks.Console # 控制台 sink(调试用,可选) 💡 Serilog 是 C# 最流行的结构化日志库,装完才能 using Serilog;

📂 配置代码放 DaqMonitor.UI/App.xaml.cs 的 OnStartup 里(全局只配一次),业务代码到处用 Log.Information(...)。

using Serilog;
Log.Logger = new LoggerConfiguration()
    .MinimumLevel.Information()
    .WriteTo.File("logs/daq-.txt", rollingInterval: RollingInterval.Day)
    .CreateLogger();

Log.Information("设备 {Device} 已连接", device.Name);
Log.Warning("点位 {Point} 超阈值 {Value}", 3, 200);
Log.Error(ex, "采集异常");

② 接全局异常（🟦）

AppDomain.CurrentDomain.UnhandledException += (s, e) =>
    Log.Fatal(e.ExceptionObject as Exception, "未处理异常");

⚠️ 重点 & 易踩坑

项 说明
⭐ 结构化参数 Log.Information("值 {V}", v) 不是字符串拼接，便于检索
⭐ 日志分级 别全写 Info，错误用 Error，否则日志无用
🔥 忘了 CloseAndFlush 程序退出前 Log.CloseAndFlush()，否则最后几条丢
🔥 日志无限增长 用滚动文件(按天) + 保留策略

🟢 基础题

配置 Serilog 写文件，分别写一条 Info 和一条 Error，并验证文件生成。

🟡 进阶题

用结构化参数写：Log.Warning("点位 {Point} 超阈值 {Value}", 3, 200)，打开日志文件确认不是字符串拼接、而是 Point=3 Value=200 可检索格式。

🔴 挑战题

接全局异常：AppDomain.CurrentDomain.UnhandledException 里 Log.Fatal(ex, "未处理异常")，并验证程序崩溃前最后一条日志被写盘（别忘了退出 Log.CloseAndFlush()）。

✅ 答案（进阶题核心）

Log.Warning("点位 {Point} 超阈值 {Value}", 3, 200);  // 结构化，非拼接

🧩 多场景应用：报警 + 日志还能怎么用

报警引擎和日志不是"弹个窗"就完了，企业里这样落地： - 多端通知：UI 闪烁（本项目 GaugeControl.Level 变红）+ 声音 + 弹窗；进阶对接钉钉/企业微信机器人、邮件、短信（HTTP 调用，见 M11）。 - 报警落库 + 报表：报警事件写 M4 数据库，M10 报表统计"每班报警次数 Top10"——管理层要看的。 - 看板大屏：车间大屏红字滚动当前未恢复报警（Andon 系统雏形）。 - 日志集中检索：Serilog 不止写文件，可接 Seq / ELK（均开源免费），多台上位机日志汇总，按"点位/级别/时间"秒查——工业运维标配。 - 对接 MES / SCADA：报警和设备状态通过 M7（OPC UA / MQTT）上报车间系统。

🔗 本项目已落地的实证： ① M6 报警引擎已驱动 GaugeControl.Level 让超限点位表盘变橙/红（跨模块复用，控件零改）； ② 新增 DiagnosticsService（采集统计 + 环形日志）已接进 MainWindow 的「诊断/调试」Tab——日志不只在文件里，界面上就能看、能排查。
