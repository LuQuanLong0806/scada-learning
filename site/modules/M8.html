Day 1 — MVVM 重构 + 配置化

一句话讲清楚

MVVM = 把 UI(XAML) 和逻辑(ViewModel) 用"绑定"解耦：ViewModel 只管数据和命令，界面自动跟着变。配置化 = 把易变的参数挪到外部文件，改配置不改代码。

前端类比秒懂

MVVM 前端
View (XAML) 模板 / JSX
ViewModel 组件逻辑 / store
INotifyPropertyChanged 响应式 ref / reactive
[RelayCommand] 事件处理函数
appsettings.json .env 配置

分点精讲

① ViewModel（CommunityToolkit.Mvvm）（🟧🟦）

🔧 必装 NuGet(在 src/DaqMonitor.UI/ 目录执行): bash cd src/DaqMonitor.UI dotnet add package CommunityToolkit.Mvvm 💡 CommunityToolkit.Mvvm 是微软官方 MVVM 库,用源生成器自动写 INotifyPropertyChanged 样板。

📂 DaqMonitor.UI/ViewModels/MainViewModel.cs · namespace DaqMonitor.UI.ViewModels

using System.Threading.Tasks;
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;

namespace DaqMonitor.UI.ViewModels;

// ⚠️ 必须标 partial(源生成器需要),必须继承 ObservableObject
public partial class MainViewModel : ObservableObject
{
    [ObservableProperty] private string _status = "就绪";
    [ObservableProperty] private double _currentValue;

    [RelayCommand]
    private async Task StartAsync()
    {
        Status = "采集中...";
        // 调设备/引擎，结果自动反映到界面
    }
}

🔬 掰开揉碎：[ObservableProperty] 到底生成了什么（源生成器 Source Generator）

手写 INotifyPropertyChanged 又臭又长（每个属性要 OnPropertyChanged）。CommunityToolkit.Mvvm 用 Roslyn 源生成器在编译期帮你生成样板代码： - 你写：[ObservableProperty] private double _currentValue; - 编译后自动生成：public double CurrentValue { get => _currentValue; set { _currentValue = value; OnPropertyChanged(); } } + 实现 INotifyPropertyChanged。 - [RelayCommand] 同理生成 StartCommand 属性和 ICommand 实现。 - 为什么比手写好：零样板、不会漏写 OnPropertyChanged、编译期就检查类型。进阶阅读：源生成器原理 https://learn.microsoft.com/dotnet/csharp/roslyn-sdk/

🔬 掰开揉碎：DI 生命周期怎么选（WPF + EF Core 场景）

AddSingleton / AddScoped / AddTransient 选错会出诡异 bug： - Singleton（全局唯一）：PointStore、AlarmEngine、AcquisitionPipeline——整个程序就一份，所有窗口/线程共享。 - Scoped（一次作用域一份）：DbContext 必须用 Scoped（或每次 new）。原因见 M4「变更追踪缓存」——一个 DbContext 用太久缓存膨胀、并发冲突。在 WPF 里常手动开 using var scope = provider.CreateScope() 包住一次数据库操作。 - Transient（每次都新建）：轻量无状态工具类用，别给有状态的服务用（会各自一份、不共享）。 - 循环依赖：A 构造函数要 B、B 又要 A → 启动即炸，拆出公共依赖到第三个类。

🔧 工程对齐补丁:手写 MVVM 工程版(2026-08-25 审计后补)

本讲义正文用 CommunityToolkit.Mvvm 源生成器([RelayCommand] 一行搞定);真实工程 DaqMonitor 没装 Toolkit,是手写版——面试官若让你白板写,考的是手写版。两版关系:Toolkit 源生成器帮你在编译时生成了下面这套手写代码;看懂手写版,才知道 Toolkit 在送你什么。逐行版见 逐行导读 · 第 8 站。

补丁① 手写 RelayCommand(工程 29 行全文的核心)

public class RelayCommand : ICommand        // WPF 按钮只认 ICommand,不懂"方法"
{
    private readonly Action<object?> _execute;              // 按下执行
    private readonly Func<object?, bool>? _canExecute;      // 能不能按(可空=永远能)

    public RelayCommand(Action<object?> execute, Func<object?, bool>? canExecute = null)
    { _execute = execute; _canExecute = canExecute; }

    public event EventHandler? CanExecuteChanged            // ← 精华:转接 WPF 全局重询机制
    {
        add { CommandManager.RequerySuggested += value; }
        remove { CommandManager.RequerySuggested -= value; }
    }
    public bool CanExecute(object? p) => _canExecute?.Invoke(p) ?? true;
    public void Execute(object? p) => _execute(p);
}

💡 CanExecuteChanged 那个怪写法:WPF 需要知道"现在按钮该亮该灰",这里不自己维护订阅名单,而是搭上 CommandManager 的全局重询班车(焦点变化等时机自动全量重问)。

补丁② INPC 手写模板 + 为什么要有 PointView(工程两件套)

// INPC 属性模板(背到肌肉记忆——忘了 OnChanged() 界面就不刷新,WPF 新手第一大坑)
public double Value
{
    get => _value;
    set { _value = value; OnChanged(); }        // 存值 + 喊话,WPF 听到名字精准刷新那一格
}
private void OnChanged([CallerMemberName] string? n = null)   // 编译器魔法:自动报"是谁变了"
    => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(n));

为什么 UI 不能直接绑 SensorPoint:①它是 struct,赋值=复印,绑定引擎跟踪不了复印过程——值变了 UI 不知道 ②struct 没有属性通知。所以造一个 class 版的展示模型 PointView(每个属性都会喊话)——这就是"领域模型 vs 展示模型"分离,前端类比:原始数据 → 组件里的 reactive 包装。

ObservableCollection 的局限(高频追问):它只在行增删时通知 UI;行内属性变了它不管——所以列表元素自己必须是 INPC(=PointView)。

补丁③ 三个工程写法速记

  • IValueConverter:Convert 正向(数据→界面,如 bool→"采集中"),ConvertBack 单向绑定时返回 Binding.DoNothing。前端类比:filter/pipe。
  • DataGrid TemplateColumn + DataTemplate:自定义单元格(工程塞的是自绘仪表盘),前端类比:scoped slot。列内 {Binding Id} 的上下文自动切到"每个元素"——v-for 的作用域切换。
  • 按钮双条件:CanStartAcquisition => 有权限 && !IsRunning——工业软件按钮不是"给不给点",是"该角色在该状态下该不该点"。
