记忆与复习机制 · 间隔重复版(Spaced Repetition)🧠

优先级定位:🔴 必执行 · 这是 30 天路线的"防漏机制"——没有它,Day 1 学的 CRC 到 Day 25 已经忘 80%,你前面 24 天的努力直接打水漂 核心问题:旧 30 天路线只有 Day 7 / 14 / 24 三次"二刷/三刷",间隔太稀疏,Week 1 学完到 Week 2 复习中间已经遗忘 70%,复习等于重学。本机制换 Ebbinghaus 数字版:1d / 3d / 7d / 15d / 30d 五段间隔重复 技术来源:🟦 Ebbinghaus 遗忘曲线(1885,实验心理学的开山研究) · 🟧 Anki / Quizlet / SuperMemo 的 SM-2 算法 · 🟧 React useEffect 依赖触发模型(类比记忆触发模型) 给简历加的能力:面试时被追问"为什么 0xA001 不是 0x8005"——你 3 秒内 答出来,不假思索。这不是"聪明",是间隔重复训练出来的肌肉记忆。13-15K 和 8-10K 的差距,70% 在这里 前置:30 天作战路线 · 代码肌肉训练手册 · 面试高频知识点速记卡 · 面试问答逐字稿 30 题

为什么需要间隔重复(用前端语言讲)

核心类比:React.useEffect 的依赖数组——只有 deps 变了,effect 才重跑。记忆也是一样的:只有"快忘了才复习"才能让大脑把这条信息标记为"重要、长期保留";每次都趁热复习(像每次 render 都重跑 effect),大脑反而判它"已知、不用存",复习反而破坏记忆。

为什么旧路线的"周末刷上周"不行:周一学的 CRC,周日复习时你已经忘掉 65%(Ebbinghaus 曲线:24h 后忘 66%,7d 后忘 75%)。复习 = 重学一遍,效率极低,而且因为重学不痛苦,大脑记不住。

SRS(Spaced Repetition System)为什么有效:

时机 大脑反应 记忆效果
学完立刻复习(0-2h) "这个我已经知道了" 几乎无效(浅层加工)
1 天后复习 "诶,有点模糊,要想想" 强记忆(大脑判定"重要")
3 天后复习 "得回忆几秒" 更强记忆(深度提取)
7 天后复习 "卡壳了,翻一下笔记" 长期固化(迁移到长期记忆)
15-30 天后还能复习起来 "这题我熟" 永久掌握

Anki / Quizlet 的底层就是这个:算法在"你快忘了"那一刻把卡片推给你,复习成本最低、收益最高。Anki 用 SM-2 算法,SuperMemo 用 SM-18,本质都是 Ebbinghaus 曲线的工程化。

前端工程师的天然优势:你已经习惯"配 useEffect deps",配间隔重复就是同样的事——给每个知识点挂"复习触发器",到点自动触发。30 天 = 30 个 effect,每天 15-20 分钟跑一遍。

Week 1 闭卷 30 题 · 主干打底(C# / Modbus / 串口 / 通道)

C# 陷阱(5 题)

W1.01 List<Point> 改字段(list[0].X = 99)为什么会丢?

答:struct 值类型,索引器返回拷贝,改拷贝原对象没动。 快忘点:面试官追问"struct 性能一定比 class 好吗?"→ 错,>16 字节拷贝成本陡增。

W1.02 async void 为什么是炸弹?

答:异常无法 catch + 调用方无法 await + 进程崩溃。唯一合法场景是 WPF 事件处理器。 快忘点:追问"库代码里 async void 怎么改"→ 一律 async Task,内部包 try-catch。

W1.03 UI 线程调 .Result 为什么死锁?

答:.Result 阻塞 UI,async 内部 await 要回 SynchronizationContext(UI 线程),两边互等。 快忘点:追问"库代码怎么避免"→ 加 ConfigureAwait(false)。

W1.04 Count++ 在多线程下为什么会丢数?

答:读-改-写三步非原子,用 Interlocked.Increment(ref _count)。 快忘点:追问"为什么 lock 也行但慢"→ lock 有上下文切换成本。

W1.05 闭包捕获 for 循环变量(for(i...) Task.Run(()=>i))为什么全打 5?

答:Lambda 捕获变量引用,循环结束 i=5,C# 5+ 已修但老代码要 var local = i。 快忘点:追问"foreach 也踩吗?"→ C# 5+ foreach 已修,for 没修。

Modbus / 协议(5 题)

W1.06 Modbus RTU 帧格式?

答:[从站地址 1B][功能码 1B][数据 NB][CRC16 低字节][CRC16 高字节]。 快忘点:CRC 低字节在前(很多新人搞反)。

W1.07 Modbus CRC16 初值为什么是 0xFFFF,不是 0?

答:让全 0 数据也产生非零校验,否则全 0 数据 CRC=0 看不出错。 快忘点:追问"多项式为什么 0xA001"→ 0x8005 的位反转。

W1.08 Modbus 寄存器是大端还是小端?CRC 呢?

答:寄存器值大端,CRC 低字节在前(混合标准,最坑)。 快忘点:面试官故意问"CRC 也是大端吧"→ 错,这是陷阱。

W1.09 寄存器地址 40001 对应协议里的什么?

答:40001 是引用地址(文档写法),协议里功能码 03 的"寄存器地址"从 0 开始,40001 → 0。 快忘点:追问"为什么有 4 区段(0/1/3/4)"→ Modbus 规范:线圈/输入线圈/输入寄存器/保持寄存器。

W1.10 粘包/半包的本质是什么?怎么解?

答:串口/TCP 是字节流无消息边界。解法:帧头 + 长度域 + 缓冲重组 + CRC 校验。 快忘点:追问"找不到帧头怎么办"→ 清空缓冲,否则内存无限涨(生产事故源)。

PLC(3 题)

W1.11 S7.Net 连 PLC,IsConnected 返回 true 就一定通吗?

答:不,只表示 TCP 通。PLC 进 STOP 模式后 IsConnected=true 但 LastErrorCode != 0。 快忘点:追问"怎么真判断"→ 看 LastErrorCode + 心跳读已知点位。

W1.12 DB1.DBW0 / DB1.DBD4 / DB1.DBX0.0 区别?

答:DBW = Word(2 字节)、DBD = Double Word(4 字节)、DBX = 位(1 bit)。 快忘点:追问"读浮点用哪个"→ DBD,但 PLC 端要声明 Real 不是 DInt。

W1.13 S7-1200 默认优化访问的 DB 块能用 S7.Net 读偏移吗?

答:不能,必须右键 DB 块取消"优化访问"才能按偏移读。 快忘点:追问"为什么"→ 优化访问用符号寻址,偏移不固定。

EF Core(3 题)

W1.14 EF Core 为什么推荐 IDbContextFactory<T> 不直接注入 DbContext?

答:DbContext 不是线程安全,并发 SaveChangesAsync 抛异常。Factory 每次返回新实例。 快忘点:追问"AddDbContext + Scoped 行不行"→ WPF 没请求作用域,Factory 更稳。

W1.15 SaveChangesAsync 高频调用为什么慢?怎么优化?

答:每条都开事务 + 网络往返。改批量:AddRange + 单次 SaveChanges,性能提 10-50 倍。 快忘点:追问"SQLite 单写者怎么处理"→ 用 Channel 串行化所有写。

W1.16 AsNoTracking() 什么时候用?

答:只读查询用,跳过变更追踪提升性能。写场景必须用 tracking。 快忘点:追问"全局禁用 tracking 怎么做"→ UseQueryTrackingBehavior(NoTracking)。

Prism / MVVM(3 题)

W1.17 MVVM 三层职责?

答:View(XAML 界面) / ViewModel(状态+逻辑,INotifyPropertyChanged) / Model(数据)。 快忘点:追问"ViewModel 能引用 View 吗"→ 不能,违背 MVVM。

W1.18 SetProperty(ref _x, value) 内部做了什么?

答:① 比较新旧值(EqualityComparer)② 不等则赋值 ③ 触发 PropertyChanged 事件。 快忘点:追问"为什么不直接 _x = value"→ 不触发事件 UI 不更新。

W1.19 ICommand.CanExecute 返回 false 会怎样?

答:绑定的 Button 自动 IsEnabled=false(灰显)。 快忘点:追问"CanExecute 什么时候重算"→ CommandManager.InvalidateRequerySuggested() 或显式 RaiseCanExecuteChanged。

TCP(3 题)

W1.20 TCP ReceiveAsync 返回 0 表示什么?

答:对端正常关闭(FIN),不是错误,必须 return 触发重连。 快忘点:追问"返回 0 抛异常吗"→ 不抛,静默返回 0。

W1.21 TCP 心跳和接收循环为什么要并行 Task?

答:接收循环 await ReceiveAsync 阻塞,心跳要定时发送,串行会卡。 快忘点:追问"用 LinkedTokenSource 干嘛"→ 一个 cancel 同时停心跳和接收。

W1.22 重连退避为什么加抖动(jitter)?

答:避免多客户端同时重试撞服务端(thundering herd),抖动 = 随机 + baseDelay。 快忘点:追问"指数退避上限"→ 必须封顶,否则 Math.Pow(2, 20) 溢出。

MQTT / 上云(3 题)

W1.23 MQTT QoS 0 / 1 / 2 区别?

答:0=至多一次(火警丢)、1=至少一次(可能重复)、2=恰好一次(性能差)。 快忘点:追问"工业现场选哪个"→ 1(默认),2 性能差慎用。

W1.24 MQTT ClientId 重复会怎样?

答:后连的踢先连的(broker 默认行为)。 快忘点:追问"怎么避免"→ MachineName + Guid 保证唯一。

W1.25 MQTT 通配符 + 和 # 区别?

答:+ 单层(device/+/data 匹配 device/A/data 不匹配 device/A/B/data),# 多层。 快忘点:追问"# 必须在主题最后吗"→ 是,MQTT 规范要求。

报警 / 性能(2+2 题)

W1.26 报警为什么要回滞(hysteresis)?

答:阈值边界抖动时报警反复触发/消除。回滞:超上限才报,降到下限以下才解除。 快忘点:追问"回滞带怎么定"→ 经验值,通常是量程的 2-5%。

W1.27 dotnet counters 监控什么指标?

答:GC / ThreadPool / 内存 / CPU / 工作集。生产 7×24 跑必看。 快忘点:追问"GC Gen 2 计数涨说明什么"→ 大对象进老代,可能内存泄漏。

W1.28 7×24 跑 3 天内存从 100MB 涨到 1GB,怎么排查?

答:dotnet gcdump 抓快照对比,找对象数量异常增长(event 没退订 / Channel 没消费)。 快忘点:追问"怎么验证修好了"→ 再跑 3 天看曲线平稳。

调试(1 题)

W1.29 条件断点和数据断点区别?各自适合什么场景?

答:条件断点 = 表达式为真时断(类似 if(x)debugger)。数据断点 = 内存地址被改时断(适合"字段莫名被改")。 快忘点:追问"数据断点对 class 字段有效吗"→ 无效,只能监视值类型字段地址。

W1.30 讲讲你 DAQMonitor 项目的架构(1 分钟 STAR)?

C# 陷阱深挖(5 题)

W2.01 🔁 W1.02 升级:async void 内的异常,AppDomain.UnhandledException 能 catch 吗?

答:能捕获但不能阻止进程崩溃(除非 TaskScheduler.UnobservedTaskException 配置)。 快忘点:追问".NET Core vs .NET Framework 行为差"→ Core 默认不崩(可配),Framework 默认崩。

W2.02 ConfigureAwait(false) 在 WPF 和库代码里分别该不该加?

答:WPF UI 代码不用(要回 UI 线程更新),库代码必须加(避免 SynchronizationContext 捕获,防死锁)。 快忘点:追问"ASP.NET Core 还需要吗"→ 不需要(无 SyncContext)。

W2.03 lock(this) 为什么不行?

答:this 是公开引用,外部代码可以 lock 同一对象 → 死锁 + 隐蔽耦合。用 private readonly object _gate = new()。 快忘点:追问"lock(typeof(T)) 行吗"→ 也不行,typeof 返回的 Type 对象是公开的。

W2.04 🔁 W1.04 升级:Interlocked.CompareExchange 怎么实现无锁 CAS?

答:CPU 原生指令(lock cmpxchg),比较 + 交换一次性原子完成。失败重试。 快忘点:追问"CAS 的 ABA 问题"→ 加版本号(Interlocked 的 ref int version 模式)。

W2.05 IDisposable + finalizer 什么时候一起用?

答:只有封装非托管资源(IntPtr/文件句柄/COM)才需要 finalizer 兜底。纯托管不需要。 快忘点:追问"SafeHandle 是干嘛的"→ 已包 finalizer,优先用而不是自己写。

Modbus / 通信深化(5 题)

W2.06 🔁 W1.06 升级:Modbus RTU 帧之间要等多久?

答:3.5 字符静默时间(9600bps 约 4ms)。否则接收方分不清帧边界。 快忘点:追问"Modbus TCP 也要吗"→ 不用,TCP 用 MBAP 头里的长度域定位。

W2.07 Modbus 异常码 0x01-0x04 含义?

答:0x01 非法功能码 / 0x02 非法数据地址 / 0x03 非法数据值 / 0x04 从站设备故障。 快忘点:追问"异常响应帧怎么识别"→ 功能码最高位置 1(如 0x83 = 0x03 异常)。

W2.08 RS485 一主多从,主站轮询时间怎么算?

答:每从站响应时间 × 从站数 + 帧间隔。如 10 从站 × 50ms = 500ms 一轮,1s 轮询 2 次。 快忘点:追问"从站太多轮询不够怎么办"→ 拆多个总线 / 提波特率 / 用 TCP。

W2.09 🔁 W1.10 升级:粘包缓冲区找不到帧头为什么必须清空?

答:设备掉线发垃圾数据时缓冲区无限涨,最终 OOM 崩进程。 快忘点:追问"清空会丢真数据吗"→ 不会,真数据有 AA55 帧头,清的是垃圾。

W2.10 串口 BytesToRead 等够数据时为什么用 Thread.Sleep(10) + 超时,不直接 Read()?

答:SerialPort.Read 没数据会阻塞卡死,无法超时退出。轮询 BytesToRead + Sleep 可控。 快忘点:追问"生产怎么写"→ 用 NModbus4 库的 async Task<ushort[]> 异步。

EF Core 深化(3 题)

W2.11 PointStore 内存索引 + SQLite 双写为什么不一致?

卡片 1(来自 B1)

【正面】手写 Modbus CRC16,初值为什么是 0xFFFF 而不是 0?
【反面】让全 0 数据也产生非零校验,否则全 0 数据 CRC=0 看不出错。
【为什么】CRC 的本质是"多项式除法余数",初值 0 会让前导 0 字节不影响余数 → 失去检错能力。
   初值 0xFFFF 等价于"开头先 XOR 一个 0xFFFF",保证前导 0 也能改余数。
【踩坑警告】① 多项式必须 0xA001 不是 0x8005(Modbus 用反向多项式)
           ② 8 次循环不是 16 次
           ③ Modbus 协议 CRC 低字节在前(很多新人搞反)
           ④ 5 分钟白板写不出 = 你背得不够熟

卡片 2(来自 B2)

【正面】Channel<T> 为什么比 ConcurrentQueue<T> 更适合生产者消费者?
【反面】Channel 是异步无锁(单 reader / writer 时),ConcurrentQueue 是全局锁。
【为什么】Channel 内部用 Segment 链表 + Volatile 读,SingleReader=true 时完全无锁。
   配合 `await ReadAllAsync()` 自然支持异步消费,不阻塞线程。
   ConcurrentQueue 的 `TryDequeue` 是同步阻塞,高频场景吃 ThreadPool。
【踩坑警告】① 必须 `Writer.Complete()` 否则消费者永远 await
           ② 必须 `CancellationToken` 否则退出卡死
           ③ `SingleReader=true` 一定要配对(多个消费者会乱)
           ④ 不要用 `async void` 处理消费异常(会吞)

卡片 3(来自 B16)

【正面】TCP 粘包状态机遇到"假帧头"(AA 后不是 55)怎么办?
【反面】只移除 1 字节(AA),从下一字节继续扫 0xAA,不要整段丢弃。
【为什么】AA 可能是真帧头被噪声污染的前一字节,丢整段会丢真数据。
   丢 1 字节最坏情况是丢一个垃圾字节,数据完整性最高。
【踩坑警告】① `RemoveAt(0)` 是 O(N),高频场景用 ArrayPool + 环形缓冲
           ② 缓冲找不到 AA 必须清空(否则内存爆)
           ③ CRC 校验范围要对(头 + 长 + 载荷,不含 CRC 本身)
           ④ `RemoveRange(0, idx + total)` 不是 `RemoveRange(idx, total)`

卡片 4(来自 C1)

【正面】`bus.DataArrived += async (s, e) => await SaveAsync(e)` 为什么是炸弹?
【反面】Lambda 是 `async void`(EventHandler 签名),SaveAsync 抛异常时进程直接崩,没 Task 能 catch。
【为什么】async void 的异常直接抛到 SynchronizationContext,WPF 默认会让进程崩溃。
   编译器生成的状态机无法被外部观察,取消/超时/异常全部"消失"。
【踩坑警告】① 改同步入队:bus.DataArrived += OnData;然后在 OnData 里 _ = Task.Run(...)
           ② 更优:用 Channel<T> 串行化(异步消费,不阻塞事件源)
           ③ WPF Button_Click 是 async void 唯一合法场景,但内部必须 try-catch + 日志
           ④ 库代码见到 async void 99% 是 bug

卡片 5(来自 B5)

【正面】报警回滞的 HighThreshold 和 LowThreshold 谁大?低报场景反过来吗?
【反面】高报:High > Low(80 / 70,超 80 报,降到 70 以下解);低报:Low < High(20 / 30,低 20 报,升到 30 以上解)。
【为什么】回滞本质是"两个阈值中间是迟滞区",防止边界抖动反复触发。
   高报场景:Low 是"解除阈值",必须在 High 之下才有效果。
   低报场景反之。
【踩坑警告】① 必须边沿检测(只在 wasActive ≠ nowActive 触发事件),否则反复刷 UI
           ② 回滞带大小 = 量程 2-5%(温度量程 100℃ → 带 2-5℃)
           ③ 报警风暴(1 秒 100 条)要聚合去重(同点位 1 分钟 1 次)
           ⑤ 锁要细(只锁 Evaluate + 事件触发,不要锁整个 OnSample)
