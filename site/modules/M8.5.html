M8.5 · Prism 企业级 MVVM(深度版)

优先级定位:🔴 必学(15K 加分) · JD 高频点名"会 Prism 优先" 技术来源:🟧 第三方 NuGet Prism.DryIoc(dotnet add package Prism.DryIoc) 给简历加的能力:让上位机用行业事实标准 MVVM 框架(Prism)重构,从"手写 RelayCommand + ViewModel 字面量"升级到模块化 + Region + 事件聚合器 + 对话服务 —— 这是 13K → 15K 的关键工程化能力。 前置:M0(WPF/XAML)、M8(MVVM 基础)、M9(DI 容器)

⏱️ 阅读路径(按时间预算选入口) - 3 分钟:看「模块目标」— 知道 Prism 是企业级 MVVM 事实标准(JD 高频点名) - 30 分钟:加看 Day 1 PrismBootstrapper 替代手写 Bootstrapper - 3 小时:全文精读 + Day 2 RegionManager 模块化 + Day 3 EventAggregator 跨 VM 通信 + Day 4 DialogService - 🎯 面试高频:RegionManager(动态注入 View) / EventAggregator(pub/sub 解耦) / ViewModelLocator 命名约定 / Prism vs CommunityToolkit.Mvvm 选型 - 🔁 配套复习:代码肌肉 B17 EventAggregator 简化版 / B18 ViewModelLocator · 间隔重复表

模块目标

学完这份你能: 1. 理解为什么用 Prism 比 CommunityToolkit.Mvvm 强(模块化是企业级核心,不是写法问题) 2. 用 PrismBootstrapper 替代手写 Bootstrapper,DI 容器切到 DryIoc 3. 用 Region + Navigation 把单窗口拆成多 View(Header / DeviceList / Chart / Alarm 各自独立) 4. 用 IEventAggregator 跨 ViewModel 通信(替代手写 event 满天飞) 5. 用 IDialogService 弹出标准对话框(替代 MessageBox.Show 玩具写法)

Day 1 — 为什么用 Prism + PrismBootstrapper 重构

一句话讲清楚

Prism = 微软官方背书的企业级 MVVM 框架(前 Pattern & Practices 团队),提供模块化 + Region + 事件聚合器 + 导航 + 对话服务五件套,前端类比:React 生态里 Prism ≈ Next.js + React Router + Zustand + Radix Dialog 的合体 —— 不是教你写 ViewModel,是教你怎么把 50 个 View/VM 装配成大型应用。

前端类比秒懂

Prism 概念 前端类比 说明
PrismBootstrapper Next.js 启动入口 应用入口,DMA 配置在此
ViewModelLocator.AutoWire React 的 connect() / Vue 自动 VM 绑定 View 和 VM 按命名约定自动配对
Region React Router <Outlet/> / Vue <router-view/> 占位区,运行时注入 View
Module Catalog Webpack 动态 import / lazy load 按需加载模块(可插件化)
IEventAggregator Redux / EventBus / mitt 跨组件(VM)通信,松耦合
IDialogService Radix Dialog / Ant Design Modal 标准弹窗服务,不用自己 new Window
DelegateCommand useCallback / useEvent 标准命令封装,带 CanExecute
INavigationAware React Router useEffect 监听路由 进入/离开页面时回调

🟢 知识点 1:为什么不用 CommunityToolkit.Mvvm?

很多人会问:M0 不是讲 CommunityToolkit.Mvvm 吗([ObservableProperty]/[RelayCommand]),为什么还要 Prism?

关键区别: | 维度 | CommunityToolkit.Mvvm | Prism | |---|---|---| | 作用范围 | VM 微观(属性/命令代码生成) | 应用宏观(模块化/Region/导航/对话) | | 学习成本 | 低(注解就会) | 中(要懂容器/Region/事件聚合) | | 适合场景 | 小到中型项目 | 大型企业项目(50+ View) | | 是否可叠加 | ✅ 可和 Prism 共存 | ✅ 也支持 BindableBase |

结论:Prism 和 CommunityToolkit.Mvvm 不是二选一,可以一起用。建议: - 顶层架构:Prism(Bootstrapper/Region/Navigation/Dialog) - VM 内部:CommunityToolkit.Mvvm 的 [ObservableProperty](更简洁)

JD 真相: - 写"会 CommunityToolkit.Mvvm" → 10K 岗位(初级) - 写"会 Prism 模块化开发" → 13-15K 岗位(中级) - 两个都会 → 15K 稳

🟡 知识点 2:Bootstrapper 重构(从手写 DI → PrismBootstrapper)

改造前(项目现状,M9 自定义 Bootstrapper):

// DaqMonitor.Core/AppServices/Bootstrapper.cs
public static class Bootstrapper
{
    public static IServiceProvider Build()
    {
        var services = new ServiceCollection();
        services.AddSingleton<IDevice, SimulatedDevice>();
        services.AddSingleton<AcquisitionPipeline>();
        services.AddSingleton<MainViewModel>();
        return services.BuildServiceProvider();
    }
}

改造后(Prism 版):

// DaqMonitor.UI/App.xaml.cs
public partial class App : Application
{
    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);
        var bootstrapper = new DaqBootstrapper();
        bootstrapper.Run();
    }
}

public class DaqBootstrapper : PrismBootstrapper
{
    // 1. 创建主窗口 Shell(顶级容器)
    protected override Window CreateShell() => Container.Resolve<MainWindow>();

    // 2. 注册 VM / 服务 / 业务
    protected override void RegisterTypes(IContainerRegistry containerRegistry)
    {
        // 设备 + 管线(DI 注入)
        containerRegistry.RegisterSingleton<SimulatedDevice>();
        containerRegistry.RegisterSingleton<AcquisitionPipeline>();
        containerRegistry.RegisterSingleton<PointStore>();
        containerRegistry.RegisterSingleton<AlarmEngine>();

        // Region 页面注册
        containerRegistry.RegisterForNavigation<DeviceListView>();
        containerRegistry.RegisterForNavigation<ChartView>();
        containerRegistry.RegisterForNavigation<AlarmView>();

        // 对话框
        containerRegistry.RegisterDialog<SettingDialog, SettingDialogViewModel>();
    }

    // 3. 配置模块目录(可选,大型项目用)
    protected override IModuleCatalog CreateModuleCatalog() =>
        new ModuleCatalog()
            .AddModule<AcquisitionModule>()
            .AddModule<ReportingModule>();

    // 4. 选 DI 容器(DryIoc 性能最好)
    protected override void ConfigureContainerAdapter(DryIocContainerAdapter adapter)
    {
        // Prism 默认配 DryIoc,不用动
    }
}

逐行白话: - CreateShell() —— 主窗口(Shell),所有 Region 都装在它里面。Container.Resolve<MainWindow>() 用 DI 创建(支持构造注入)。 - RegisterTypes() —— 全局 DI 注册。RegisterSingleton / RegisterScoped / RegisterTransient 三种生命周期。 - RegisterForNavigation<TView>() —— 把 View 注册成可"导航到",配合 Region 使用。 - RegisterDialog<TView, TViewModel>() —— 注册对话框,后续用 IDialogService.Show("name") 弹出。 - CreateModuleCatalog() —— 模块目录,把项目拆成多个模块(类似 React 的 lazy chunk)。

🔬 掰开揉碎:Prism 的 Region 是什么?

前端类比:React Router 的 <Outlet/>。

<!-- MainWindow.xaml(Shell) -->
<Window>
    <Grid>
        <Grid.ColumnDefinitions>
            <ColumnDefinition Width="200"/>
            <ColumnDefinition Width="*"/>
        </Grid.ColumnDefinitions>

        <!-- 左侧导航 -->
        <StackPanel Grid.Column="0">
            <Button Content="设备列表" Command="{Binding NavigateCommand}" 
                    CommandParameter="DeviceListView"/>
            <Button Content="实时曲线" Command="{Binding NavigateCommand}" 
                    CommandParameter="ChartView"/>
            <Button Content="报警日志" Command="{Binding NavigateCommand}" 
                    CommandParameter="AlarmView"/>
        </StackPanel>

        <!-- 关键:Region 占位,运行时 Prism 注入对应 View -->
        <ContentControl Grid.Column="1" 
                        prism:RegionManager.RegionName="MainRegion"/>
    </Grid>
</Window>

// MainViewModel
public class MainViewModel : BindableBase
{
    private readonly IRegionManager _regionManager;
    public DelegateCommand<string> NavigateCommand { get; }

    public MainViewModel(IRegionManager regionManager)
    {
        _regionManager = regionManager;
        NavigateCommand = new DelegateCommand<string>(Navigate);
    }

    private void Navigate(string viewName) =>
        _regionManager.RequestNavigate("MainRegion", viewName);
}

效果:点"设备列表"按钮,右侧 MainRegion 立刻显示 DeviceListView,左侧导航不变 —— 页面局部刷新,完全单窗口应用(不像 WinForms 要 new 多个 Form)。

⚠️ 常见坑点预警

坑 说明
ViewModelLocator 命名约定 View 命名 XxxView,VM 必须叫 XxxViewModel(同命名空间),否则不自动绑定
BindableBase vs ObservableObject Prism 用自己的 BindableBase.SetProperty;CommunityToolkit 用 [ObservableProperty],两者不能在一个 VM 混用
Container.Resolve 滥用 服务定位器反模式,优先构造注入。Resolve 只在没法构造注入时用
RegisterForNavigation 缺失 忘注册,RequestNavigate 不报错只黑屏(Prism 默默丢弃)
DryIoc 容器规则 默认严格,循环依赖直接抛异常(比 Microsoft.Extensions.DependencyInjection 严格)

🧪 三档练习

  • 🟢 基础:把 MainViewModel 改成继承 BindableBase,把 private string _title; public string Title { get => _title; set => SetProperty(ref _title, value); }
  • 🟡 进阶:在 MainWindow 加一个 Region,点击按钮切换 3 个 View(DeviceList/Chart/Alarm)。 ✅ 答案:见上面 RegionManager 示例。
  • 🔴 挑战:DAQMonitor 现在是单 MainWindow,改造为 Shell + 3 个 Region(Header / Sidebar / Main),每个 Region 装一个 View。 ✅ 答案:<ContentControl prism:RegionManager.RegionName="HeaderRegion"/> 等,Bootstrapper 里 RegisterForNavigation 注册 3 个 View。

💡 工控导师说(真实战例)

我接手过一个 5 年的 WinForms 老项目,500+ Form 互相 new Form2().Show(),改一个字段 100 个文件连锁改。重写成 Prism + Region 之后,Shell 不动,每个业务模块独立,改配方管理只动 RecipeModule,5 倍效率提升。企业项目 Region 是刚需,不是过度设计。

Day 2 — 模块化 + 导航 + ViewModel 通信

一句话讲清楚

模块化 = 把 100 个 View 拆成 5 个 Module(采集/可视化/报警/报表/配置),每个 Module 独立开发和加载;导航 = 进入/离开 View 时回调(传参/暂停采集/保存草稿);IEventAggregator = 跨 VM 通信(替代手写 event 满天飞)。

🟢 知识点 1:模块化(IModule)

前端类比:Webpack code-splitting / React.lazy。

// AcquisitionModule.cs —— 把采集相关 View/Service 打包
public class AcquisitionModule : IModule
{
    public void RegisterTypes(IContainerRegistry containerRegistry)
    {
        containerRegistry.RegisterSingleton<AcquisitionPipeline>();
        containerRegistry.RegisterForNavigation<DeviceListView, DeviceListViewModel>();
    }

    public void OnInitialized(IContainerProvider containerProvider)
    {
        // 模块加载完成时回调(类似 React useEffect onMount)
        var pipeline = containerProvider.Resolve<AcquisitionPipeline>();
        pipeline.Start();
    }
}

// Bootstrapper 注册模块
protected override IModuleCatalog CreateModuleCatalog() =>
    new ModuleCatalog()
        .AddModule<AcquisitionModule>()
        .AddModule<VisualizationModule>()
        .AddModule<AlarmModule>();

模块加载方式: - AddModule<T>() —— 直接代码注册(常用) - AddModule<T>(InitializationMode.OnDemand) —— 按需加载(用户点开"配方管理"才加载,启动快) - 目录加载:从 ./Modules/*.dll 动态发现(插件化,工业 SCADA 常用)

🟡 知识点 2:导航参数 + 生命周期回调(INavigationAware)

前端类比:React Router 的 useParams + useEffect。

public class DeviceDetailViewModel : BindableBase, INavigationAware
{
    private int _deviceId;

    // 进入页面时(每次都调,类似 useEffect deps)
    public void OnNavigatedTo(NavigationContext navigationContext)
    {
        _deviceId = navigationContext.Parameters.GetValue<int>("id");
        LoadDevice(_deviceId);
    }

    // 离开页面时(类似 useEffect cleanup)
    public void OnNavigatedFrom(NavigationContext navigationContext)
    {
        SaveDraft();   // 离开前保存草稿
    }

    // 是否允许复用同一实例(类似 React.memo)
    public bool IsNavigationTarget(NavigationContext navigationContext) => false;
}

// 调用方
_regionManager.RequestNavigate("MainRegion", "DeviceDetailView", 
    new NavigationParameters { { "id", 42 } });

🔴 知识点 3:IEventAggregator 跨 VM 通信(必备)

前端类比:Redux / mitt / RxJS Subject。

为什么不用普通 event: - 普通 event 要求订阅方和发布方互相知道对方类型(强耦合) - 跨 VM 通信(比如 AlarmViewModel 要通知 ChartViewModel 高亮某个点),用 event 要在 Bootstrapper 里手动 a.Xxx += b.OnXxx,50 个 VM 时连线崩溃 - IEventAggregator 是 ** Pub/Sub 模式**,发布方不认识订阅方

// 1. 定义事件
public class AlarmTriggeredEvent : PubSubEvent<AlarmEventArgs> { }
public class AlarmEventArgs
{
    public int PointId { get; init; }
    public double Value { get; init; }
    public DateTime Time { get; init; }
}

// 2. AlarmViewModel 发布
public class AlarmViewModel
{
    private readonly IEventAggregator _ea;
    public AlarmViewModel(IEventAggregator ea) => _ea = ea;

    public void OnAlarm(AlarmEventArgs e) => 
        _ea.GetEvent<AlarmTriggeredEvent>().Publish(e);
}

// 3. ChartViewModel 订阅(不用知道 AlarmViewModel 存在)
public class ChartViewModel
{
    public ChartViewModel(IEventAggregator ea)
    {
        ea.GetEvent<AlarmTriggeredEvent>()
          .Subscribe(OnAlarm, ThreadOption.UIThread, keepReferenceAlive: false);
    }

    private void OnAlarm(AlarmEventArgs e)
    {
        // 在 UI 线程高亮报警点(报警发生时实时刷新曲线)
        HighlightPoint(e.PointId, e.Time);
    }
}

关键参数: - ThreadOption.UIThread —— 自动切到 UI 线程(不用 Dispatcher.Invoke) - keepReferenceAlive: false —— 弱引用,VM 销毁时不泄漏(默认 true 容易内存泄漏,见 C# 陷阱讲义 陷阱 1) - filter: e => e.PointId == _currentPoint —— 过滤订阅(只关心当前点)

⚠️ 常见坑点预警

坑 说明
模块循环依赖 ModuleA 引用 ModuleB,ModuleB 引用 ModuleA,DryIc 抛异常。设计时单向依赖
IEventAggregator 忘退订 Subscribe 默认 keepReferenceAlive:true,VM 销毁前要 Unsubscribe,否则泄漏
导航参数类型不匹配 GetValue<int>("id") 如果传了 string,返回 default(0),不抛异常 → 神秘 bug
IsNavigationTarget 返回 true 同一参数复用同一 VM 实例,可能拿到上次数据。一般返回 false 每次新建

  • 🟡 进阶:加 INavigationAware 让 DeviceDetailVM 接收 ?id=N 参数。
  • 🔴 挑战:DAQMonitor 拆成 5 个 Module(采集/可视化/报警/报表/配置),每个独立加载,Module 之间用 EventAggregator 通信。

Day 3 — 对话服务 + 命令 + 调试技巧

🟢 知识点 1:IDialogService(替代 MessageBox.Show)

前端类比:Radix Dialog / Ant Design Modal。

问题:MessageBox.Show("确认删除?") 是玩具写法,生产要: - 自定义样式(主题色) - 异步回调(用户点了什么按钮) - MVVM 友好(对话框本身是个 VM)

// 1. Bootstrapper 注册对话框
containerRegistry.RegisterDialog<ConfirmDialog, ConfirmDialogViewModel>();

// 2. ConfirmDialogViewModel 实现 IDialogAware
public class ConfirmDialogViewModel : BindableBase, IDialogAware
{
    public string Title { get; set; } = "确认";
    public event Action<IDialogResult> RequestClose;
    public DelegateCommand YesCommand { get; }
    public DelegateCommand NoCommand { get; }

    public ConfirmDialogViewModel()
    {
        YesCommand = new DelegateCommand(() => 
            RequestClose?.Invoke(new DialogResult(ButtonResult.OK)));
        NoCommand = new DelegateCommand(() => 
            RequestClose?.Invoke(new DialogResult(ButtonResult.Cancel)));
    }

    public bool CanCloseDialog() => true;
    public void OnDialogClosed() { }
    public void OnDialogOpened(IDialogParameters parameters)
    {
        Title = parameters.GetValue<string>("title");
    }
}

// 3. 调用方
_dialogService.ShowDialog("ConfirmDialog", 
    new DialogParameters { { "title", "确认删除设备?" } },
    result =>
    {
        if (result.Result == ButtonResult.OK)
            DeleteDevice();
    });

🟡 知识点 2:CompositeCommand(组合命令)

前端类比:同时触发多个 useCallback。

场景:点"启动采集"按钮,同时启动 N 个设备 —— CompositeCommand 把 N 个子命令组合,任一 CanExecute=false 父命令就禁用。

public class MainViewModel
{
    public CompositeCommand StartAllCommand { get; }

    public MainViewModel(IEnumerable<IDevice> devices)
    {
        StartAllCommand = new CompositeCommand();
        foreach (var d in devices)
        {
            var cmd = new DelegateCommand(() => d.Connect(), () => d.State == DeviceState.Offline);
            StartAllCommand.RegisterCommand(cmd);
        }
    }
}

🔴 知识点 3:Prism 调试技巧

  • Container.GetContainer() 输出 DryIoc 全表(开发期看注册对不对)
  • IRegionManager.Regions 看当前所有 Region 和 View
  • EventAggregator 没收到事件:99% 是忘 keepReferenceAlive:false(强引用 + 没退订)
  • 导航失败静默:用 RequestNavigate(..., result => { if (!result.Result.HasValue) /* 失败 */ }) 第三参数捕获

⚠️ 常见坑点预警

坑 说明
DialogResult 必须传 RequestClose?.Invoke(null) 会抛异常,要传 new DialogResult(ButtonResult.OK)
DelegateCommand<T> T 是值类型 不能传 null,要不传就用无参 DelegateCommand
CompositeCommand 监听子命令 子命令 CanExecuteChanged 要正确触发(看 DelegateCommand.ObservesProperty)
Prism 版本碎片 8.x 和 9.x API 变化大,固定版本(8.1.97 最稳)
