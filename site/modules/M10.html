Day 1 — 历史聚合查询（LINQ GroupBy）

Day 1 — 历史聚合查询（LINQ GroupBy）

企业报表的本质：把海量原始记录，按"维度+时间窗"聚合成少量统计行。

前端/JS 类比 C# 对应
SELECT point, MIN(v),MAX(v),AVG(v) FROM t GROUP BY point GroupBy(p => p.Id) + Min/Max/Average
arr.reduce((acc,cur)=>..., {}) LINQ 链式 Where → GroupBy → Select
时间戳过滤 t >= from && t <= to Where(p => p.Timestamp >= from && p.Timestamp <= to)

① 聚合服务（🟦 LINQ + 🟩 DateTime，纯计算、可单测）

// DaqMonitor.Core/Reporting/ReportService.cs
public sealed class ReportService
{
    public IReadOnlyList<PointStat> Aggregate(IEnumerable<SensorPoint> points, DateTime from, DateTime to)
    {
        return points
            .Where(p => p.Timestamp >= from && p.Timestamp <= to)  // 时间窗过滤
            .GroupBy(p => p.Id)                                    // 按点位分组
            .Select(g => new PointStat(                            // 注意:PointStat record 的字段顺序
                PointId: g.Key,                                    // 参 [前置类型定义](前置类型定义_学员粘贴版.md)
                Count:  g.Count(),
                Min:    g.Min(p => p.Value),
                Max:    g.Max(p => p.Value),
                Avg:    g.Average(p => p.Value),
                First:  g.Min(p => p.Timestamp),
                Last:   g.Max(p => p.Timestamp)))
            .OrderBy(s => s.PointId)
            .ToList();
    }
}

真实可行性：这段代码已在 DaqMonitor.Tests/ReportServiceTests.cs 里用 6 条样例点验证（含窗外点被正确过滤），dotnet test 全绿。

⭐ 重点 & 🔥 坑

项 说明
⭐ 聚合放在 Core 而非 UI 纯逻辑、无 IO，才能单测；UI 只负责"展示/导出"
⭐ 时间窗边界 >= from && <= to 含端点；跨时区存 DateTime 注意 Kind
🔥 大数据量 真历史库要用 SQL GROUP BY（EF IQueryable），别把全表拉内存再 LINQ；本演示数据量小，内存聚合 OK
🔥 空窗返回空集合 不是 null，UI 绑定 ItemsSource 才不崩

✏️ 练习

  1. 给 ReportService 加一个 AggregateByHour(points, from, to)，按"小时"分桶（提示：p.Timestamp.Date.AddHours(p.Timestamp.Hour) 当 key）。
  2. 加一条"报警次数"统计：传入 IEnumerable<AlarmEvent>，按点位统计触发次数。

✅ 答案

// 1) 按小时
.GroupBy(p => p.Timestamp.Date.AddHours(p.Timestamp.Hour))
// 2) 报警次数(AlarmEvent 在前置类型定义里)
alarms.GroupBy(a => a.PointId)
      .Select(g => new { PointId = g.Key, Triggers = g.Count() });

③ 导出 Excel（🟧 ClosedXML）

🔧 必装 NuGet(在 src/DaqMonitor.UI/ 目录执行,UI 项目里弹 SaveFileDialog): bash cd src/DaqMonitor.UI dotnet add package ClosedXML 💡 ClosedXML 是开源 Excel 操作库,不需要装 Office,纯托管代码生成 .xlsx。 (QuestPDF 同理:dotnet add package QuestPDF,社区许可证免费)

📂 DaqMonitor.UI/Reporting/ReportExporter.cs · namespace DaqMonitor.UI.Reporting 💡 用到 PointStat(M10 Day 1 / 前置类型定义)

// DaqMonitor.UI/Reporting/ReportExporter.cs
using System.Collections.Generic;
using ClosedXML.Excel;
using DaqMonitor.Core.Reporting;

namespace DaqMonitor.UI.Reporting;

public static class ReportExporter
{
    public static void ExportToExcel(IEnumerable<PointStat> stats, string path)
    {
        using var wb = new XLWorkbook();
        var ws = wb.Worksheets.Add("报表");
        ws.Cell(1,1).Value = "点位"; ws.Cell(1,2).Value = "样本数";
        ws.Cell(1,3).Value = "最小"; ws.Cell(1,4).Value = "最大";
        ws.Cell(1,5).Value = "平均"; ws.Cell(1,6).Value = "首条"; ws.Cell(1,7).Value = "末条";
        int r = 2;
        foreach (var s in stats)
        {
            ws.Cell(r,1).Value = s.PointId; ws.Cell(r,2).Value = s.Count;
            ws.Cell(r,3).Value = s.Min;      ws.Cell(r,4).Value = s.Max;
            ws.Cell(r,5).Value = s.Avg;      ws.Cell(r,6).Value = s.First;
            ws.Cell(r,7).Value = s.Last;     r++;
        }
        ws.Columns().AdjustToContents();   // 自动列宽
        wb.SaveAs(path);
    }
}

真实可行性：DAQ Monitor 的 MainWindow 已加"导出报表"按钮 + 起止时间选择器，命令里 new ReportService().Aggregate(...) → ReportExporter.ExportToExcel(...)，UI 构建 0 错误 0 警告，点按钮即生成真实 .xlsx。

PDF（🟧 QuestPDF，可选）：Document.Create(cfg => cfg.Page(p => p.Content().Table(...)))，适合要盖章/打印的场景。

⭐ 重点 & 🔥 坑

项 说明
⭐ ClosedXML 不用装 Office 纯托管代码生成 xlsx，部署机干净
⭐ 用 using 包 XLWorkbook 不释放会锁文件
🔥 路径权限 导出到用户选的路径（SaveFileDialog），别写 C:\Program Files
🔥 大数据导出 流式写、分批，避免一次性占内存

  • 本模块 = M4(存储) + M5(可视化) + M6(报警) 的收口：没有前面三块，报表就是无米之炊。
